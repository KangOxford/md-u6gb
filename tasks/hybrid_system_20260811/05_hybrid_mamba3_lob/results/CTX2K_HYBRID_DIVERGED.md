## 2. 排除项

| 假设 | 排除依据 |
|---|---|
| 梯度爆炸未被裁剪 | `MAX_GRAD_NORM=1.0` 默认开启（`train_helpers.py:694`），裁剪在生效 |
| 数据/步数/优化器不同 | 两条臂逐字相同：同数据、同 32,000 优化器步、Muon lr=0.01、ssm_lr=8e-4、wd=0.005、K=2 |
| 长上下文本身不稳 | **baseline 也是 2k，它没事**——所以不是长度，是长度 × attention |
| 与 500 上下文的 hybrid 同因 | 那一条跑满 32,000 步没发散（CE 单调降到 0.5284）——所以不是架构本身 |

**唯一的交集：这一层 attention，在 52,000 token 上。** 500 上下文时它只看 13,000。

## 3. 候选成因（未验证，按可测性排序）

| 候选 | 为什么可疑 | 怎么测 |
|---|---|---|
| bf16 attention 在 52k 上的数值 | softmax 分母是 52,000 项求和，bf16 尾数 8 位 | 把 attention 的 softmax 强制 fp32，重跑 6000 步 |
| NoPE + 4× 键集合 | 无显式位置信号时注意力分布随长度摊平，输出尺度漂移 | 开 `HYBRID_ATTN_PE=True` 对照跑 |
| Muon 在 attention 块上过激 | Muon lr=0.01 是为 13k 调的 | 只降 attention 块的 lr，或整体降到 0.005 |
| warmup 太短 | `WARMUP_END=0.01` → 320 步，长上下文下可能不够 | 提到 0.05（1,600 步） |

**loss 每 2000 步才记一次**，定位不到比「4000–6000 之间」更细。若要重跑，第一件事是把日志频率提到每 50–100 步，否则下一次还是只能得到同样粗的区间。
