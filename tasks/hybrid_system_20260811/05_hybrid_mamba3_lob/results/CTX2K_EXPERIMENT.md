# 2,000 条上下文：两条臂端到端实验（2026-08-12 起）

**问题**：把 half-half 的窗口从 500 条（cond250/gen250）拉到 **2,000 条（cond1000/gen1000）**，
hybrid 相对 baseline 的优势会变好、变差，还是不动。

**为什么这不只是敏感性测试**：往后真正要用的就是长窗口，所以两条臂都得在 2k 上**重新训练**，
不是拿 500 上下文的模型去跑长推理。

---

## 1. ⭐ 这是一个 token 完全配平的对照

| | 500 上下文（已完成） | **2k 上下文（本次）** |
|---|---:|---:|
| PER_GPU_BSZ × MSG_SEQ_LEN | 4 × 500 | **1 × 2000** |
| 节点 × GPU | 4 × 4 = 16 | **2 × 4 = 8** |
| GRAD_ACCUM K | 1 | **2** |
| 每样本 token | 13,000 | **52,000** |
| 每 micro-batch token | 0.8320M | 0.4160M |
| **每优化器步 token** | **0.8320M** | **0.8320M** |
| 优化器步数 | 32,000 | 32,000 |
| **计划总 token** | **26.624B** | **26.624B** |

**每步 token 与总 token 逐位相同**，样本数（64 vs 16）差 4 倍只是切法不同。
这一组数由训练脚本自己打印（`[Tokens]` 行，本次新增），不靠手算。

配平的成立依据是实测：**递归模型的激活显存只取决于每步消息总数，与怎么切成样本无关**。
同样每步 1,000 条消息，bsz4×250 / bsz2×500 / bsz1×1000 的峰值是 35.79 / 35.78 / 35.71 GB。

---

## 2. 实测的代价

| 臂 | 500 上下文 | **2k 上下文** | 倍数 |
|---|---:|---:|---:|
| baseline | 0.313 s/步 | **0.571 s/micro** (1.75 it/s) | 1.82× |
| hybrid | 0.313 s/步 | **0.787 s/micro** (1.27 it/s) | 2.51× |

hybrid 更贵的部分来自注意力的二次项：

```
注意力 FLOPs 比 = (1 × 52000²) / (4 × 13000²)
                = 2.704e9 / 6.76e8
                = 4.0×
```

**把四段 500 拼成一段 2000，注意力代价正好 4 倍。** 这不是实现开销，这就是长程注意力的定价。

预计墙钟（64,001 micro 步）：baseline **10.2 h**，hybrid **14.0 h**。

---

## 3. 数据侧：窗口数降 4 倍，短文件掉 0.06%

窗口是**非重叠**的（`seqs_per_file = (usable_rows − max_offset) // n_messages`），
所以 n_messages 从 500 变 2000：

```
每进程分片 = 1,877,168 micro 步 × 4 样本 = 7,508,672
总样本（2 进程） = 15,017,344
理论值（500 版 60,105,460 / 4） = 15,026,365
实测/理论 = 99.94%
```

**消息数 < 2,000 的文件会被整个丢掉**（`seqs_per_file=0`），实测只损失 **0.06%**，可忽略。
这一项是起跑前标出的风险，现已量化关闭。

### 过程中修掉的五个坑

| 坑 | 症状 | 判据 |
|---|---|---|
| 删配置只删定义不删引用 | `HYBRID_ATTN_HEADS: unbound variable`，起飞前一刻死 | `set -u` 把错误推迟到运行期 |
| 两条臂共用 `GEN_BATCH` 路径 | 后起的覆盖先起的，**无任何报错** | 并行跑同一脚本时产物路径必须带臂名 |
| 两条臂共用节点日志 | `training_5992008_node0.log` 被两臂交错写 | attach 下 SLURM_JOB_ID 相同、procid 也相同 |
| 训练 srun 缺 `-w` | `--nodes=2` 落在 4 节点分配上，srun 自选 | 两臂可能撞到同几个节点 |
| 清场与起飞之间有间隙 | 清空后 90 秒内被别的会话抢回 | 清场必须紧贴闸门，同一次启动内完成 |

### 速率与预计终点

```
baseline  1.81 it/s → 64,001 / 1.81 = 9.8 h   （时限 10.5 h，能跑满 32,000 优化器步）
hybrid    1.22 it/s → 64,001 / 1.22 = 14.6 h  （时限 13.5 h，约到 29,600 步）
分配剩余  14:13
```

两臂**会停在不同步数**，所以对照点由守望器取「两臂共有的最高 checkpoint」，
先停的那个把步号落盘、后停的照抄——否则两臂会在不同步号上评测。
