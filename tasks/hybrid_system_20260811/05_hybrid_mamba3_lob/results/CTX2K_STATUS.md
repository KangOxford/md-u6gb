| 问 | 看什么 |

## 5. 自动接力

改成**一个链式控制器**（`code/chain_manager.sh`），因为原来两个独立守望器缺一个分支：

```
训练停了 ──┬── 跑够了      → 评测
           └── 分配没了    → 换个分配续训，续不上才评测
```

两个独立守望器表达不了这个分支，因为「该不该续」取决于**另一件事**（还有没有空闲
allocation），而那不是任何一个守望器自己的状态。分配到期会让它们误判为「训练结束」，
在半截 checkpoint 上开跑，产出一份看起来正常的错误结果。

控制器的三条判据：

| 判什么 | 用什么 | 为什么不用别的 |
|---|---|---|
| 训练在不在跑 | 该臂节点上的 compute 进程数 | squeue RUNNING 不代表在训练（有过 4h27m 空转） |
| 现在到第几步 | checkpoint 目录里的数字子目录 | 日志里的计数是 micro 步，不是优化器步 |
| checkpoint 在哪 | 从该臂节点日志实时读 | 目录名含 wandb id，每次续训都变 |

读不到时一律按「还在跑」处理：误判成停会毁掉结果，误判成跑只是晚一轮。
