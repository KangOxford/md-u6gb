# Hybrid·阶段7：根因——NoPE 只关了训练路径，两条生成路径仍在注入位置编码（2026-08-12）

> **一句话**：阶段6 看到的「CE 赢了、生成崩了」不是架构现象，是我自己的 bug。`use_positional_encoding` 这个开关我只加在了训练路径上，**生成路径无条件给每个 query 和 key 加了模型从没见过的正弦位置编码**。

---

## 1. 缺陷本身

`src/s5/transformer.py` 里 `TransformerBlock` 有三条前向路径。开关只判了一条：

| 路径 | 用在哪 | 是否判 `use_positional_encoding` |
|---|---|:---:|
| `__call__` | **训练**、loss、留出集 CE | ✅ 判了（180 行） |
| `prefill` | 生成时的条件窗口 | ❌ **无条件加**（原 224 行） |
| `__call_inference__` | 生成时的逐 token 解码 | ❌ **无条件加**（原 268 行） |

hybrid 按 Nemotron 配方是 **NoPE**，`registry.py:316` 的默认值就是 `False`，`HYBRID_ATTN_PE` 从未设置。于是：

```
        ┌──────────── 训练（模型在这个分布上学了 32,000 步）────────────┐
  x ───►│  norm ─► attention                                          │
        └──────────────────────────────────────────────────────────────┘

        ┌──────────── 生成（模型从没见过这个输入）─────────────────────┐
  x ───►│  x + sinusoidal_PE ─► norm ─► attention                     │
        └──────────────────────────────────────────────────────────────┘
                  ↑
            凭空多出来的信号，幅值 ±1，与激活同阶
```

`prefill` 里还有第二处内部不一致：

```python
output = self(input_sequence)                      # ← 无 PE（正确）
...
h = self.norm1((input_sequence + pe)...)           # ← 有 PE
k = ... h ...; v = ... h ...                       # ← 缓存的 K/V 来自另一个输入
```

**返回的激活与缓存的 K/V 来自两个不同的输入。** 连条件窗口的 cache 都是错的。

---

## 2. 为什么它精确解释了阶段6 的每一个现象

| 阶段6 的观察 | 这个 bug 的预测 | 对上了吗 |
|---|---|:---:|
| 留出集 CE 一路领先 0.75–0.87%，八个点位无例外 | CE 走 `__call__`，**不受影响**；测到的是模型真实水平 | ✅ |
| 生成质量却全线变差 | 只有生成路径被污染 | ✅ |
| 12,000 步时 hybrid 生成**更好**，32,000 步时**更差** | 训练越久越依赖 attention，**污染它的代价按依赖程度放大** | ✅ |
| 引用越远越差（101–250 档 −10.72 pp 最惨） | PE 扰动随**绝对位置**增长，远距离回指受创最重 | ✅ |
| 训练本身完全正常 | 训练根本没经过出问题的代码 | ✅ |

**没有一条需要额外假设。** 而我原先的 exposure-bias 解释虽然也能凑出时间顺序，却**解释不了 CE 与生成的分离为何如此干净**——exposure bias 应当让两者都退化，只是程度不同。

---

## 3. 为什么所有闸门都看不见它

这是本次最值得记住的部分：

```
   训练 ──► loss ──► 收敛曲线      ┐
   CE 评测 ─────────────────────►  ├─ 全部走 __call__（干净的那条）
   4 次冒烟测试 ────────────────►  ┘

   生成 ──► LOB-Bench / 引用成功率 ─► 只有这里走 prefill + __call_inference__
```

**两条路径不一致，不可能压低任何一条 loss 曲线。** 所以：32,000 步训练、8 个 CE 点位、4 次冒烟，没有任何一个能报警——它们全都在另一条路径上。唯一能看见它的是端到端 benchmark，而 benchmark 的输出长得像「架构结论」。

> 我差一点就把它写成了架构发现。挡住这一步的是**反转的形态不对**：hybrid 的回指率在 12k→32k 几乎不动而 baseline 涨了 11.43 pp。真实的架构劣势应当是两条都涨、一条涨得慢；**「一条停住了」是故障的形状，不是劣势的形状。**

## 4. 修复与回归测试

修复：`prefill` 与 `__call_inference__` 都改为判 `self.use_positional_encoding`（commit `facf656`）。

新增 `src/s5/tests/test_transformer_decode_parity.py`——**从第一次提交起就该存在的测试**：同一份输入分别走并行前向和 prefill+逐步解码，要求数值一致。

**并且验证了这个测试抓得住 bug**（一个在修好和修坏时都通过的测试等于没有测试）：

| 场景 | `use_pe=True`（对照） | `use_pe=False`（hybrid） |
|---|---|---|
| 修复后 | ✅ pass | ✅ pass |
| 把 bug 打回去 | ✅ pass | ❌ **fail，误差 1.992** |

对照组 `use_pe=True` 在两种情况下都通过，证明这个测试测的是**路径一致性**，而不只是「有没有 PE」。

---

## 5. ⭐ 对既有结论的影响：**是下界，不是上界**

@12000 的生成结果**同样是在这个 bug 下产生的**。也就是说阶段3、阶段5 里 hybrid 赢下的每一个数，都是在 **attention 被污染**的情况下取得的：

| 阶段5 已确认的结论（bug 状态下） | 修复后的预期方向 |
|---|---|
| WS-21 配对差 −0.03326，三 seed 同号 | 只会更好或持平 |
| L1 精确 +2.22 pp，三 seed 同号 | 只会更好或持平 |
| 六分箱全同号，远端 +13.10 pp | 远端受 PE 扰动最重，**修复后应当更大** |

**这些结论不会因为修复而失效，只会被低估。** 需要重测的是**数值**，不是**方向**。

反过来，阶段6 的「hybrid 更差」**全部作废**。
