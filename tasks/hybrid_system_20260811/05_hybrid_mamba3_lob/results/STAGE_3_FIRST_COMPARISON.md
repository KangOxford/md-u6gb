## 2. ⭐ 机制判据 P2：增益随引用距离单调放大

这是本阶段最重要的一张表。P2 在 2026-08-12 早些时候写进 `BASELINE.md` 时的原话是：

> 若 hybrid 真靠内容寻址取胜，**增益应集中在老年龄段**（101–250 与 before-window），而不是均匀分布。若观察到均匀提升，那更像训练噪声或容量差，而非 attention 起了作用。

实测：

| 引用年龄（往回多少条消息） | n | baseline | hybrid | **Δ (pp)** |
|---|---:|---:|---:|---:|
| 1–10 | 114,670 | 88.78% | 90.65% | +1.87 |
| 11–25 | 62,417 | 89.12% | 91.07% | +1.95 |
| 26–50 | 35,606 | 80.20% | 85.63% | **+5.44** |
| 51–100 | 24,914 | 69.21% | 78.60% | **+9.40** |
| **101–250** | 12,440 | 48.83% | **61.63%** | **+12.79** |
| before-window | 138,058 | 26.80% | 29.36% | +2.56 |

```
 Δ (pp)
  13 ┤                                    ●  101-250
  11 ┤
   9 ┤                          ●  51-100
   7 ┤
   5 ┤                ●  26-50
   3 ┤                                          ● before-window
   1 ┤  ●     ●  1-10 / 11-25                     （结构上够不着）
   0 ┼──┬─────┬────────┬─────────┬─────────┬──────────
      1-10  11-25   26-50    51-100   101-250
```

**两条都对上了**：

1. **增益随距离单调放大**：1.87 → 1.95 → 5.44 → 9.40 → 12.79 pp。近端几乎没动（本来就 89%，没空间），远端翻倍式改善。
2. **`before-window` 只涨 2.56 pp**。这一档占全部引用的 35.7%，但目标**根本不在窗口里**——既有 oracle 审计给出真实续段的可见率上限 88.18%，剩下的没有任何历史行可指。**attention 在这里无处可看，所以它不该涨，也确实没怎么涨。**

第 2 条是这组证据里最有说服力的部分：**效应恰好出现在机制说它该出现的地方，恰好消失在机制说它不该出现的地方。** 一个「多训了几千步」或「多了 5% 参数」的解释无法产生这种选择性——那会把整条曲线平移。

### 与「训练更久」的对照

baseline 自己从 12k 训到 32k，L1 精确率 63.46% → 74.89%（+11.43 pp）。把那条曲线也拆开看，可以直接检验「hybrid 是不是只等价于多训几千步」。这一步待 hybrid@32000 出来后补做（届时四条曲线可以放在一张图上）。

## 3. 事件类拆分：一个必须报告的分布变化

| 类型 | baseline n | hybrid n | 变化 | baseline L1 | hybrid L1 |
|---|---:|---:|---:|---:|---:|
| delete | 387,264 | 385,302 | −0.5% | 63.57% | 65.17% |
| cancel（部分撤） | 841 | 1,209 | **+43.8%** | 13.67% | 20.18% |
| **execution（成交）** | 8,885 | **14,117** | **+58.9%** | — | — |

hybrid 生成的**成交消息多了 59%**，部分撤单多了 44%。这是一个实质的分布变化，不是噪声量级。两种读法都要摆出来：

- **可能是好事**：真实市场里成交并不罕见，baseline 可能生成得太少；这也可能是 WS-21 改善 16.7% 的一部分来源。
- **可能是隐患**：成交多意味着簿被吃得更快，若过量会改变价格动态。

**现在无法判定哪一种**，因为需要与真实数据的事件类型占比对照。这一项列入下一阶段必测。

（execution 两臂都是 0%，因为引用解析在现行管线里只作用于 event_type 2/3，成交拿全新 order id——按构造未定义，见阶段2报告 §4.1。）

## 4. 我预测错了一件事：LOB-Bench 显著改善了

阶段1/2 我明确写过：

> LOB-Bench 测的是逐行边际分布，对事件先后近乎不敏感（打乱时间顺序反而好 13.7%，21 项里 13 项恰好零变化）。命题 H 主张的「精确回指」是纯动态能力，**(7.3) 结构上测不到**。故 (7.3) 降级为非劣效闸门。

实测 WS-21 **改善 16.7%**，远超我预期的「测不到」。

**必须说清楚的是：这个数字目前还不能算显著。** 既有标定给出的跨 seed 散布是 **16.6%**（3 seed，WS-21 0.20949–0.24424），而本次相对改善是 16.7%——**恰好落在跨 seed 散布的量级上**。单 seed 单点，无法与 seed 噪声区分。

相比之下，(7.4) 的年龄分层是**同一次运行内跨分箱**的模式，不受跨 seed 均值漂移影响；它的单调形状才是本阶段真正立得住的证据。

**推测（待验）**：若成交/撤单的事件类型占比变得更接近真实（§3），那 21 个特征里与事件类型分布耦合的那几项会一起改善，而这与「回指能力」是两条不同的因果链。**要区分这两条，需要看逐特征的分解**，列入下一阶段。

## 5. 这一阶段还不能下的结论

| 不能说 | 为什么 |
|---|---|
| 「hybrid 比 baseline 好」 | 这是 step 12000 的中途对照，不是训练完成态。32000 步对照在跑 |
| 「WS-21 改善 16.7% 是真的」 | 单 seed，落在跨 seed 散布量级内，需要 seed 复制 |
| 「L1 精确只涨 1.57pp，效应很弱」 | 总量被两头稀释（近端无空间、窗口外够不着），机制信号在分层里 |
| 「(7.4) 三类都测了」 | execution 按构造未定义，需要先补语义 |

**已经可以说的**：在同步长、同数据、同评测代码下，把 Mamba3 主干的一层换成全局 attention 后，**引用回指能力的改善严格随引用距离放大，并在结构上不可达的分箱里消失**。这与「少数全局层恢复内容寻址」的机制预测一致，且与「多训几步 / 多几个参数」的替代解释不一致。
