# 2k 训练的运行台账 —— 两条臂各中断过几次、在哪一步、为什么

最终报告需要这一页。**「hybrid 比 baseline 差」和「hybrid 被重启的次数是 baseline 的两倍」
是两个不同的解释**，读者要能自己排除后者。这里只记事实与时刻，不下结论。

配置恒等式贯穿全程：**有效批量 = 1/GPU × 4 GPU × 节点数 × K = 80**，
即 **节点数 × K = 20**。任何一次迁移都保持它，所以中断与迁移不改变实验语义，只改墙钟。

## 2. 两次死亡的根因（不同）

### 2.1 baseline：被邻居挤死，但邻居没违规

```
GetKeyValue() timed out with key: cuda:local_topology/cuda/2 and duration: 2m
                                                        ↑ 结尾的 /2 点名缺席的 rank
```

rank2 的 CUDA context 建不起来 —— 那批节点上有别的会话的 `VLLM::Worker` 占着 92 GB。

查锁表：`claude-dfm` 声明了三个节点、`crps-wm_ft` 一个，**都留了痕**。
问题在我的闸门只查 `nvidia-smi` 不查锁表。而且把体检做细也救不了：

> 物理闸门是一个**瞬时快照**，而启动窗口有 **8 分钟**（挂 48 个 squashfs 分片 + JAX init）。
> 快照只能证明 t=0 干净，证明不了 [0, +8min] 干净。能覆盖窗口的只有**声明**。

已落规则 `tasks/node_status/PRIORITY.md` 与闸门 `code/claim_gate.sh`（先声明后体检）。

### 2.2 hybrid：NCCL 集合通信死锁

训练自己的 `StepWatchdog` 给出判定：

```
FATAL: Step watchdog timeout (1800s) at epoch 0 batch 3760. Likely NCCL deadlock.
```

外部证据一致：主线程 `wchan=futex_wait_queue`，1300 线程 `S`、**恰好 4 个 `R`**
（每 GPU 一个 CUDA 自旋线程），**0 个 orbax/checkpoint fd**（排除写盘挂死）。

> **GPU util 100% 不等于在计算。** NCCL 集合在等对端时是忙等，驱动照报满载。
> 我最初正是据此判断 hybrid 健康，判错了。可靠判据只有进度在不在变。

处置：`WATCHDOG_TIMEOUT` 1800 → **600**（稳态 ~1.3s/micro-batch，仍有 460 倍余量），
单次死锁代价从 30 分钟 × 16 GPU 降到 10 分钟。

**这是 hybrid 第二次撞集合通信问题**（前一次是 nid011166/011167 上的
`async GPU clique error` ×3，当时判为节点级问题并换了节点）。换了节点仍复发，
说明它不只是那两台机器的毛病。**这一条必须写进最终报告的威胁效度一节。**

## 3. 为什么没有把 hybrid 加到 10 节点

`10 × K2 = 20` 恒等，理论上能把 hybrid 的 ETA 从 5.2h 压到 ~2.1h，预算也够
（step 命名修好后余量 18 个节点）。没做，理由是负向的：

| 考量 | 判断 |
|---|---|
| hybrid 的实际失败模式是**节点间集合通信死锁** | 节点越多，参与集合的对端越多，死锁概率只升不降 |
| baseline 只需 2.7h、hybrid 需 5.2h | baseline 有 2.5h 余量，晚开始不影响总工期 |
| 关键路径的风险是**死锁复发**，不是节点数 | 所以成本花在降低单次死锁代价上（已做） |

## 4. 现在的自愈链路

```
训练进程 ── StepWatchdog(600s) ──► 挂死自杀，落回上一个 checkpoint
                                        │
chain_manager.sh（按臂独立，POLL=600）──┘
   活性 = Slurm step 名（base-m3-ctx2k / hyb-m3-ctx2k）
          ↓ 读不到则退回日志新鲜度，且**日志以收尾行结尾一律判死**
   进度 = .ctx2k_state_{A,B}（外化，不依赖崩溃日志）
   落脚 = 该臂自己的分配优先；被别人声明的分配直接跳过（R4）
                                        │
                                        ▼
                    launch_2k_{baseline,hybrid}.sh
                        └─ claim_gate.sh：读锁表 → 上锁 → 体检 → 不过则回滚
```

两臂都达 6400 后控制器自动转入评测：按**最近进度**配对（不求交集，`auto` 存点
按时间落，步号永远对不齐），相差 >5% 会告警并要求把两个真实步号写进报告。
