# 2k 上下文的正牌对照：hybrid 在长上下文上确实更好，而且好在理论预测的地方（2026-08-13）

**设置**：两臂在 2,000 条消息（52,000 token）上**从头训到 6,400 优化器步**，
比较点 baseline **step 6265** / hybrid **step 6258**（相差 7 步 = **0.1%**）。
同一份冻结的 3,136 条 GOOG Jan-2026 索引、cond1000 / gen1000、seed 2026、
同一份评测代码。有效批量两臂恒等（`1/GPU × 4 GPU × 4 节点 × K5 = 80`）。

**唯一改变的变量是序列长度**：500 → 2,000 条消息。模型、优化器、数据、
token 编码、有效批量全部逐字相同。

> 只能由「有一个机制专门负责远距离回指」解释 —— 而这正是往递归主干里插一层
> 全局注意力的全部理由。

### 与 500 上下文对照：符号翻转了

500 上下文（cond250 / gen250，step 32001，见 `STAGE_8_FINAL_32001.md`）：

| | baseline | hybrid | 谁好 |
|---|---:|---:|:---:|
| L1 精确（500 ctx） | **74.89%** | 74.44% | baseline（−0.60%） |

**跨行数字不可直接相减**（生成长度 250→1000，年龄分布完全不同），
但**符号翻转**这件事本身不受口径影响。

## 5. 威胁效度：两条臂的中断次数不同

见 `CTX2K_RUN_LOG.md`。当天 hybrid 被中断 **4 次**、baseline **2 次**，
根因是 checkpoint 存点路径每 900 秒新建一个纯跨节点的 NCCL clique
（`broadcast_one_to_all` 的 psum，`replica_groups=[4,4]<=[4,4]T(1,0)`，
与训练的 `[1,16]` 完全不相交），详见 `CKPT_DEADLOCK_ROOT_CAUSE.md`。

**为什么这不影响结论**：每次中断都从最近 checkpoint 精确恢复，
优化器状态、LR schedule、数据顺序都由 `state.step` 决定；
两臂最终落在 6265 / 6258，相差 0.1%。中断影响的是墙钟，不是训练轨迹。

**但有一件事必须写出来**：本轮只有一个 seed。500 上下文那轮用两个 seed
验证过配对差同号，本轮没做。§1 的单调性本身是很强的内部一致性证据
（8 个桶、单调、跨越 21 pp），但 §2、§3 的小差异应当按「未经 seed 复现」看待。

## 6. 结论

**问题**：把上下文从 500 拉到 2,000，hybrid 会不会变好？

**答**：**会，而且好在理论预测的位置。**

- 远距离回指是 hybrid 的主场：优势从 +3.7 pp（1–10 条前）单调涨到
  **+24.7 pp**（501–1000 条前），整体 +6.39 pp。
- 这**翻转了** 500 上下文下的结论（那里 baseline 在同一指标上略胜 0.60%）。
  之前的判断「优势是收敛速度不是能力」，**其适用范围仅限于短窗口**。
- 分布拟合（LOB-Bench）优势仍在但收窄（WS −11.0% → −5.4%）。
- 代价是速度：同样 3,136 条序列，hybrid 推理 **1:03:47** vs baseline **39:48**
  （+60%），因为注意力在 52k token 上是二次的。

**六步全部走完**：建立代码 → 测试 → 训练（两臂各 6,400 步）→ inference
（各 3,136 条）→ scoring（7.2 / 7.3 / 7.4 三套）→ 本报告。
