## 1. 先说一个方法上的意外收获

我原本以为 (7.4) 需要新写一个撮合引擎回放器。实际上**生成路径早就内置了仪器**：

`src/lob/inference_no_errcorr.py` 的 `get_sim_msg` 为每条生成消息写一个 provenance 位域，并逐消息落盘到 `data_gen/*_provenance_real_id_*.csv`（`:2130`）：

| 位 | 含义 |
|---|---|
| bits 0–1 | 解析层级：0=非撤单、**1=L1 精确纳秒时间戳命中**、**2=L2 同价档最近毫秒兜底**、3=完全未命中 |
| bit 2 | NaN 分支触发（D-R1） |
| bit 3 | `price ≠ price_ref`（D-R4，**已被对照证伪，不是缺陷指标**） |

解码器也现成：`src/post_training/heuristic_learning/fidelity.py` 的 `decode_provenance` / `summarise_provenance`。

所以 (7.4) 需要的是**聚合器**而不是 resolver。这也意味着测出来的是**这次运行真正做过的解析**，而不是事后重新推断的近似。

## 3. ⭐ 核心：按引用年龄分层

「年龄」= 被引用的那张单，是在生成窗口内往回第几条消息提交的；若它在条件窗口之前提交，归入 `before-window`。

| 年龄（往回多少条消息） | n | **L1 精确** | L2 兜底 | 未解析 |
|---|---:|---:|---:|---:|
| 1–10 | 101,437 | **96.45%** | 3.55% | 0.00% |
| 11–25 | 66,111 | 95.90% | 4.10% | 0.00% |
| 26–50 | 41,070 | 91.88% | 8.12% | 0.00% |
| 51–100 | 31,023 | 86.07% | 13.93% | 0.00% |
| 101–250 | 14,948 | **74.57%** | 25.43% | 0.00% |
| **条件窗口之前** | **129,150** | **39.16%** | 48.78% | 12.05% |


### 这条曲线为什么重要

**它把命题从「有道理的猜想」变成「已被部分证实的机制」。** 三点：

1. **形状对**。固定大小的递归状态在近处几乎无损（96.45%），随着要回忆的纳秒时间戳越来越久远而单调劣化。这不是「模型整体不够好」，而是**特定于距离的失效**。
2. **失效集中在长程**。近处两档（1–25 条）合计 167,548 条、L1 都在 96% 上下，几乎没有可改进空间；真正的损失在 51 条以外，尤其是 `before-window` 那 129,150 条（占全部引用的 33.7%）。
3. **它给出比总成功率锐利得多的预测**。如果 hybrid 真的靠内容寻址取胜，**增益应当集中在老年龄段**（101–250 与 before-window），而不是均匀分布。若观察到均匀提升，那更像训练噪声或容量差，而非 attention 起了作用。

这就是预注册的 **P2 机制判据**（Δ_slope）：现在 baseline 那条曲线已经在手，只等 hybrid 的第二条。

### 一个必须同时读的注意事项

`before-window` 那一档是**任何架构都够不着的一部分**。既有 oracle 审计给出：真实续段里目标 NEW 的可见率是 88.18%，剩下 11.82% 的目标早于条件窗口，没有任何历史行可指。所以这一档的 39.16% 不会被推到 100%，它的上限由可见性决定，而不是由模型能力决定。

## 4. 两个附带确认

### 4.1 execution 类：不是没测，是尚未定义

11,171 条成交消息**全部**被记为 `not-a-cancel`。原因在代码里：

```python
order_id = jax.lax.cond((event_type == 2) | (event_type == 3), ref_id, new_id)
```

引用解析只作用于 cancel(2)/delete(3)，成交(4) 拿的是**全新的 order id**，模型为成交消息生成的 ref 三元组被直接丢弃。

> 所以指令 (7.4) 要求的第三类，在现行管线里**不是「没测」而是「尚未定义」**。要测它，得先补一段语义（把 ref 解析扩展到 type 4），那是一个独立的设计决定，会改变生成出来的市场，需要它自己的证据。本报告如实标注，不用一个假数字充数。

### 4.2 部分撤单远差于全撤

| 类型 | n | L1 精确 | 完全未解析 |
|---|---:|---:|---:|
| delete（全撤） | 382,448 | 75.06% | 4.00% |
| **cancel（部分撤）** | **1,291** | **24.94%** | **22.23%** |

部分撤单只占 0.34%，但 L1 精确率只有全撤的三分之一，且五分之一完全解析不到。样本量小（1,291），下结论要谨慎，但方向值得在 hybrid 那边复看。

### 4.3 两个「不是缺陷」的数

- `nan_branch_fired`：**0 / 784,000 = 0.0000%**。D-R1 从未触发。
- `price_differs_from_ref`：146,267（占全部消息 18.66%）。**这不是缺陷计数**——既有对照显示真实市场消息也会以相近比例触发它，两个字段根本不共享参考系。保留是因为它是一个定义明确的真实数据，且删掉它会连带删掉「对照跑过」这件事的证据。
