# The environment this replication runs on. Arrived at by getting it wrong twice, so
# the reasoning is written down rather than just the versions.
#
#   /projects/public/s5e/quant_team/quant/miniforge3/bin/python -m venv --system-site-packages venv
#   ./venv/bin/pip install -r requirements-pinned.txt
#   bash code/setup_te_stub.sh          # <- required, see "The stub" below
#
# torch is deliberately NOT pinned: the venv inherits the host's 2.8.0+cu129, the only
# build with working aarch64 / GH200 support here. Installing torch into the venv would
# shadow it with something that does not run.
#
# ---------------------------------------------------------------- the forced chain
#
# There is no freedom in the first three links. Each one is forced by the one above:
#
#   diffusers main            is the only version carrying MiniMax-H3 (0.37.1 has none)
#     -> needs huggingface_hub >= 1.23   for `get_cached_repo_tree`, which
#        `diffusers.pipelines.pipeline_utils` imports and `ModularPipeline.from_pretrained`
#        reaches through `DiffusionPipeline`
#     -> hub 1.x needs transformers 5.x  (transformers 4.x wants hub < 1.0 and breaks on
#        `refresh_xet_connection_info`)
#     -> transformers 5.x removed `HybridCache`, which peft 0.17.1 imports at module
#        level, so peft must be >= 0.18
#     -> peft >= 0.18 probes transformer_engine, unguarded  ->  see "The stub"
#
# An earlier attempt went the other way -- pin transformers down to 4.57.6 to satisfy
# peft 0.17.1 -- and it *looked* fine because `from diffusers import
# MiniMaxH3Transformer3DModel` succeeded. It failed on a compute node two minutes in,
# on `ModularPipeline.from_pretrained`, a path that was never checked. Verify the
# import the job takes, not the import you thought of.
#
# ---------------------------------------------------------------- the stub
#
# peft's probe is `import transformer_engine` with no try/except, and TE's import loads
# cudnn, nvrtc and **curand** -- and libcurand exists nowhere in this environment,
# neither in the torch `nvidia/*` wheels nor on the system. So TE can never work here,
# and no amount of LD_LIBRARY_PATH fixes it: the first two libraries can be found, the
# third does not exist.
#
# `code/setup_te_stub.sh` writes an empty `transformer_engine` package into the venv,
# which shadows the host one. The probe then imports successfully and finds no
# `pytorch` attribute, so peft concludes TE-pytorch is unavailable -- which is true.
#
# (`code/env.sh` also puts the nvidia wheel lib dirs on LD_LIBRARY_PATH. That is not
# what fixes TE; it is there because other CUDA libraries are found the same way.)
