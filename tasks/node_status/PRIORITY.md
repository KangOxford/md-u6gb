# 优先级与仲裁 —— 两个会话都想要同一批卡时，谁让谁

`README.md` 回答的是「**这张空卡有没有主**」。
本文回答的是它没回答的那半个问题：「**两个会话都想要它时，谁让谁**」。

现有注册表是**对称**的：所有会话平权，锁是建议性的，唯一的不对称是「谁先声明」。
先到先得看起来公平，但它对**有状态的长训练**恰好是最差的规则——因为它在长训练
最脆弱的那一刻（resume 重启的那几分钟）判它负。

---

## 1. 触发事件（2026-08-13 10:19）

2k 对照实验的 baseline 臂在 allocation `6000412` 上重启，8 分钟后四个 rank 全灭：

```
GetKeyValue() timed out with key: cuda:local_topology/cuda/2 and duration: 2m
                                                        ↑ 结尾的 /2 就是缺席的 rank
```

JAX 分布式 init 用一个 key-value store 做集合点，每个进程把自己的 GPU 拓扑写成
`cuda:local_topology/cuda/<rank>`，rank 0 读齐全部才继续。**超时信息里的 rank 号
就是缺席者的编号**，不用猜。rank 2 的 CUDA context 建不起来，因为那批卡上有别人的
`VLLM::Worker` 占着 92 GB。

事后查锁表，那四个节点上 `claude-dfm` 声明了三个、`crps-wm_ft` 声明了一个，
**都按规矩留了痕**。违规的是我这一侧：闸门只查 `nvidia-smi`，没查锁表。

### 为什么「把体检做得更细」救不了

```
10:11  物理闸门：0 个 compute PID   →   通过
10:11–10:19  启动窗口 8 分钟（挂 48 个 squashfs 分片 + JAX init）
             ↑ 邻居在这个窗口里起来
10:19  死
```

> **快照式检查保护不了一个比它长两个数量级的窗口。**
> 它只能证明 t=0 干净，证明不了 [0, +8min] 干净。

能覆盖窗口的只有**声明**：锁在整个窗口里都摆在表上，邻居查自己的闸门时会看见。
所以承重的规则不是「查得更仔细」，而是「**进别人的分配前先留痕**」。

## 2. 三档：按「被打断的代价」排，不按到达顺序

| 档 | 谁 | 打断一次的代价 | 权利 |
|---|---|---|---|
| **T0** | 有状态**多节点**训练 | 丢进度 **+ 对照组的两条臂步数岔开，实验本身失效** | 排他；别人不得 attach |
| **T1** | 单节点训练 / 可 resume 的微调 | 回退到上一个 checkpoint（≤15 min） | 不得进 T0；可被 T0 预约 |
| **T2** | 无状态：推理、评测、烟测、vLLM、绘图 | 几分钟重启，结果不变 | 随时让路 |

T0 与 T2 的代价差**三个数量级**。这就是平权是错的全部理由。

T0 里那个「**对照可比性**」尤其容易被低估：单臂重跑只是慢，
两条臂**不同步地**重跑会让「同步号对比」这件事本身没法做，
而那正是整个实验的结论所依赖的东西。

## 3. 五条规则

| # | 规则 | 依据 |
|---|---|---|
| **R1** | **要 `--overlap` 进任何分配，先 `nodelock lock`，再起进程。** 声明在前，占用在后。 | 唯一能覆盖启动窗口的机制。§1 里 vLLM 是**无声**进来的，我的闸门无从看见 |
| **R2** | **闸门双查**：锁表无他人 live 锁 **∧** `nvidia-smi` 无他人 compute PID。任一不过就不起。 | 锁表是**意图**、`nvidia-smi` 是**事实**，两者都会单独骗人：只信锁表看不见没声明就闯进来的；只信 nvidia-smi 看不见声明了但进程还没起来的 |
| **R3** | **T0 的锁覆盖 `run` / `held`，不只是 `idle`。** 但 gtop 显示的底层四态不变，只多一个所有权徽章。 | 这是对 README 设计约束①的**扩展不是推翻**。原约束怕「lock 盖住 held 会藏起真浪费」；把**显示**与**闸门判据**分开就两者兼得 |
| **R4** | **抢占只向下，且永不由 agent 执行。** T0 想要 T2 占着的节点 → 标记并等，或交用户裁决，**不 kill**。只有用户明确点名的节点才可以 kill PID。 | 与 CLAUDE.md 禁 `scancel` 同源：判断可能错，而爆炸半径不对称 |
| **R5** | **T0 的锁按作业剩余 walltime 续租；T1/T2 短租。** README 的 `last_probe − last_activity` 判据不变。 | 长训练在 checkpoint 落盘与数据加载的间隙显存会短暂回落，10 分钟 TTL 会误杀正在跑的 T0 |

**R1 是承重件**，其余四条都是围着它的。

## 4. 机械实现

规则只写在文档里不会被遵守。落地的是一个脚本：

```
tasks/hybrid_system_20260811/05_hybrid_mamba3_lob/code/claim_gate.sh

  ALLOC=<jobid> NODELIST=<节点> OWNER=<who> TIER=T0 NOTE="..." bash claim_gate.sh
  exit 0 = 可以起飞且锁已上；4 = 别人声明过；3 = 物理体检不过
```

顺序是**先声明、后体检**，不是反过来：

| 步 | 做什么 | 为什么在这个位置 |
|---|---|---|
| ① | 读锁表，有别人的 live 锁就退出 | 一根手指都不动，R4 |
| ② | 写自己的锁 | 竞态窗口从 8 分钟缩到 ①② 之间的几秒 |
| ③ | 物理体检（`nvidia-smi`） | 这步要 ~30s，此时锁已经在保护我们了 |
| ④ | 体检不过就撤回 ② 的锁 | 绝不留下没有依据的声明 |

③ 放在 ② 后面要付回滚的代价。宁可付：反过来（体检 → 声明）会把整个 ~30s 的
体检时间重新暴露成竞态窗口。

### ④ 里那个必须记住的状态

首版的回滚是无条件 `unlock`，**第一次测试就把正在跑的 hybrid 自己的 T0 锁撤了**：
体检发现「有 compute PID」→ 回滚 → 保护没了。而那个 compute PID 正是被保护的训练本身。

> **同一条路径既是保护者又是回滚者时，必须记住进来之前的状态。**

现在 ② 会先判 `PREEXISTING`，④ 只撤本次新建的锁。

## 5. 一个副产品：step 名字决定作业会不会被预算闸门砍掉

`u6gb_16_nodes_daily_log/node_budget_monitor.py` 用正则
`^(bash|sh|zsh|ksh|csh|tcsh|-bash|interactive|pty)$` 判 step 是不是 idle。
有非 idle 名字的 step，整个作业记成 `computing`，而 **`computing` 不计入 20 节点上限**。

本仓库普遍用 `srun bash -lc '...'` 包装训练，于是 step 名就叫 `bash`。后果：

```
2026-08-13 10:40  --enforce --dry-run
  5998835  u6gb-4-node-chain  RUNNING  4  5:45:33  IDLE-HELD  only bash,bash,bash,...
                                             ↑ 这是正在训练 5 小时 45 分的 hybrid
  6000412  u6gb-4-node-chain  RUNNING  4  1:01:08  computing  ldm-synth,dfm-rs-lg488b_g3
                                             ↑ 邻居起了名字，安全
```

**正在跑的最高优先级实验被判成空转，随时可能被闸门砍掉。**

给 srun step 起个真名字（`srun --job-name=<实验名>`）不是绕过闸门，是**把度量修对**——
这个作业确实在算。两个 launcher 已加 `STEP_NAME`。

相关：README §「Slurm 判 idle ≠ 物理空闲」、
`memory/reference_u6gb_node_budget_guardrail.md` 第 6 条。
