## 实验 A：三通道投票的冗余价值

三通道：**T** = `ref_age_ns` 最近邻（阈值 τ）；**C** = `(side, price, ref_size)` 唯一匹配；
**I** = 倒数第 k 个 live NEW 指针。

无误差时单通道表现（无信息量的 oracle 上界，仅作 sanity）：
T = 100%，C = 86.3003%（3,807 次弃权），I = 100%。

**真正的问题是：某通道出错时，另两个能不能救。** 误差模型分两类：
`perturb`（真值 + δ，数值误差）与 `confuse`（换成同池内另一笔**真实**订单的值，copy 误差）。
后者才是主导形态：26tok 的 L1 命中有 **99.608%** 来自复制上下文 token。

τ = 1 μs、多数决规则下：

| 注错场景 | 命中% | **撤错单%** | ambiguous% |
|---|---:|---:|---:|
| 无注错 | 100.0000 | 0.0000 | 0.0000 |
| T 扰动 10 μs | 99.9496 | **0.0000** | 0.0504 |
| T 混淆 | 86.3003 | **0.0000** | 13.6997 |
| C 混淆 | 100.0000 | **0.0000** | 0.0000 |
| I 错位 ±1 | 86.5055 | **0.0000** | 13.4945 |
| **T+C 同时混淆** | 63.8562 | **21.2710** | 14.8728 |
| T+I 同时错 | 63.8562 | 2.7853 | 33.3585 |
| C+I 同时错 | 64.0829 | 1.7921 | 34.1250 |

**结论 A1：单通道出错时撤错单恒为 0** —— 投票确实把错误转成了诚实的弃权。

**结论 A2：T+C 同时混淆会撤错 21.27% 的单，且这 21.27% 全部来自 `consensus`**
（拆分显示 `consensus_wrong` = 21.2710%，`single_wrong` = 0.0000%）。
错误伪装成高置信共识，比低置信兜底更危险。

**结论 A3：「恰好 1 票就接受」并不是新的兜底漏洞**，各场景 `single_wrong` ≤ 0.2051%。
这一条原本担心会重蹈 26tok L2，实测站得住。

### 为什么 T 与 C 会同时错

二者共享 `(side, price)` 池作为定位基础，都从 reference 字段读值。模型若整体 copy 错
一笔订单，会同时给出那笔的 `ref_age` 与 `ref_size`，两个通道一致地指向它。
**投票在同源通道之间是伪冗余。**

### 四种裁决规则都救不了（τ = 1 μs）

| 规则 | T+C 混淆 撤错单% | I 错位 命中% | 无注错 命中% |
|---|---:|---:|---:|
| 多数决（v1 原案） | **21.2710** | 86.5055 | 100.0000 |
| 共识须含 I | 0.0000 | **0.2051** | 100.0000 |
| T+C 折为 1 票 | 0.0000 | **0.2051** | 100.0000 |
| 三票全一致 | 0.0000 | 0.2051 | **86.3003** |

「共识须含 I」和「T+C 折叠」确实消掉了伪共识，但把系统命运绑死在 I 上：I 一错位，
命中从 86.51% 崩到 0.21%。「三票全一致」则太严。**问题不在规则，在于只有两个独立信息源。**

## 实验 B：`quantity` 是一个被浪费的独立信息源（零 token 成本）

`quantity`（本次修改量）是**消息自身字段**，26tok 与 R6 都已在预测它，但两者的 resolver
都只把它当输出、没当作对候选订单的**硬约束**。

约束语义（按事件分）：DELETE 用 `candidate.remaining == msg.quantity`；
EXECUTION / partial CANCEL 用 `>=`。

目标订单满足约束的比例，以及干扰订单被过滤的比例：

| 事件 | n | 目标 `q==remaining` | 目标 `q<=remaining` | 干扰通过 `==` |
|---|---:|---:|---:|---:|
| delete | 27,205 | **100.00%** | 100.00% | **20.57%** |
| execution | 520 | 78.08% | 100.00% | 13.71% |
| partial_cancel | 64 | 0.00% | 100.00% | 8.89% |

对占 97.9% 的 DELETE，约束**永不误杀正确答案**，却过滤掉 **79.43%** 的干扰。

唯一识别率对比：

| 键 | 唯一识别率 | 新增 token |
|---|---:|---|
| `side + price` | 63.8562% | 0 |
| **`side + price + quantity` 硬约束** | **85.8253%** | **0** |
| `side + price + ref_size` | 86.3003% | +1 字段 |

「唯一但选错」= **0**，「可行集为空」= **0**（约束不会把正确答案排除）。

分事件：delete 86.2158%，execution 70.0000%，partial_cancel 48.4375%。

**结论 B1：`quantity` 硬约束值 +21.97 pp，成本为零。**

**结论 B2：`ref_size` 的边际收益只剩 +0.48 pp**（85.8253% → 86.3003%）。
原因是对 DELETE，`quantity == remaining` 恒成立、`== original` 也有 99.67%，
`ref_size` 想编码的信息 `quantity` 早就携带了。**这个字段应当从 R7 砍掉。**

## 实验 C：约束优先 resolver

裁决：`|可行集| == 1` → 直接接受（不读任何 reference 字段）；`> 1` → 可行集内
`ref_age` 最近邻 + τ；`== 0` → miss（实测 0 次）。

**分工：约束层直接定案 23,850 次（85.83%），`ref_age` 只需消歧 3,939 次（14.17%）。**

τ = 1 μs 时与「纯 T 通道、无约束」的对比：

| 注错场景 | 约束优先 命中% | 约束优先 **撤错单%** | 纯 T 命中% | 纯 T **撤错单%** |
|---|---:|---:|---:|---:|
| 无误差 | 100.0000 | 0.0000 | 100.0000 | 0.0000 |
| T 扰动 10 μs | 85.8253 | **0.0108** | 63.8562 | 0.2627 |
| T 混淆（任意同池） | 85.8541 | **9.9500** | 63.8562 | 36.1438 |
| T 混淆（可行集内） | 85.8253 | 14.1747 | 85.8253 | 14.1747 |

**结论 C1：约束层把 copy 型错误的撤错单压掉 72.5%**（36.14% → 9.95%），
因为混淆到的那笔有 79.43% 概率不满足 quantity 约束。

**结论 C2：约束层与 T 层是真正独立的**——约束读消息自身字段，T 读 reference 字段。
模型即使 reference 全错，约束层仍由正确的消息字段驱动。这是投票机制做不到的。

**结论 C3：残余风险是「混淆到可行集内的订单」**，此时约束完全失效（14.17%，与无约束相同）。
这个 14.17% 正好等于 `multi_percent`，即约束无法唯一确定的那部分。要压低它只能靠
`ref_age` 的预测质量，或引入第三个独立信号。

## 对 PLAN v1 的三处修改

| v1 决定 | 实验裁决 | v2 |
|---|---|---|
| 三通道 T/C/I 多数决投票 | **否决**（A2：T+C 同源，伪共识撤错 21.27%）| 改为**约束优先 + ref_age 消歧**两层 |
| 新增 `ref_size` 字段 | **否决**（B2：边际仅 +0.48 pp，`quantity` 已携带）| 砍掉 |
| τ 是核心参数 | **降级**（A/C：三通道下 τ 边际极小；约束优先下 τ 只影响 0.01–0.3 pp）| 保留但不是主要杠杆 |

**新增的 v2 要点**：`quantity` 硬约束（零成本 +21.97 pp）必须进 resolver。
这一条同样适用于 R6.1 现有的 78.0736% —— 它的 resolver 也没用 quantity 约束，
属于交接给 R6 接手方的一个免费改进。
