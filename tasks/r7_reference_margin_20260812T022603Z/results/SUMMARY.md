# R7 reference 匹配：安全边际与误差注入（只读实验）

时间：2026-08-12T02:29Z
状态：实验完成。未创建 R7 worktree，未修改模型，未提交训练作业。

## 为什么做这个

用户选定 R7 的主判据为 **exact-target**（撤单是否命中模型真正想引用的那一单），并要求在动
R7 代码前先回答一个问题：设计里的第二步「T 在纳秒级别没匹配上，就回退到微秒，再回退到毫秒」
到底能救回多少。

Codex 已有的审计全部是**数据侧 oracle**（用真实 continuation 测键的唯一性），没有触及
「模型预测错之后回退能不能救」。而 R7 尚未训练，没有模型预测可用。本实验用**误差注入**
绕开这个依赖：给真值 ref_age 注入受控误差 δ，测两种匹配策略在各精度下的 exact-target 命中率。
结论对任意 δ 都可读，不必等训练。

## 口径

- 数据：paired-255 的**真实**序列，`data_cond`（250 条建可见状态）+ `data_real`（250 条计数）。
- touch：CANCEL(2)、DELETE(3)、EXECUTION(4)，共 **31,630** 条；其中目标在可见历史内的
  **27,789** 条（其余 3,841 条目标早于 condition 窗口，与 Codex 审计一致）。
- **ground truth = CSV 里的 `order_id`**，因此本实验报的是 exact-target 口径。
- 时间：CSV 十进制秒经 `Decimal` 转整数纳秒，无浮点往返。
- 精度只限制**模型能输出什么**（pred 端截断到该粒度）；候选订单在簿里始终是原始纳秒。
- δ 的 ±两个方向各测一次、各计 0.5 权重，保证确定性（不使用随机数）。
- 最近邻遇距离平局判**失败**（ambiguous），不做抛硬币。

## 结果 1：安全边际 Δ_min

因为一次 touch 里所有订单共享 `now_ns`，有
`ref_age(target) − ref_age(o) = born_ns(o) − born_ns(target)`，
所以「回退到粗精度会不会撞上干扰订单」等价于一个纯静态量：同
`(side, price, original_size)` 的其他活订单中，创建时间离目标最近的距离 Δ_min。

**86.3003%（23,982 / 27,789）的可见目标完全没有干扰订单**，任意时间精度都安全。
这个数与 Codex 内容键表中 `side + price + original_ref_size` 的唯一识别率 86.3003%
**逐位相同**，两条独立实现互证口径正确。

余下 3,807 条有干扰的目标，Δ_min 分位数（ns）：

| 分位 | Δ_min |
|---|---:|
| p1 | 98 |
| p5 | 136 |

读法：**模型 ref_age 误差只要小于 1 μs，就有 97.38% 的目标不可能被干扰单抢走。**

## 结论

**一、「ns→μs→ms 逐级回退」在截断语义下几乎无效，建议整段删掉。**
截断匹配的失败模式是 **pred 落进一个空桶**，而不是「桶里候选太多」。加宽桶解决的是后者，
真实发生的是前者：δ=1 ns 就把 ns 精度从 100% 打到 0%，回退到 μs 也只救回 49.02%。

**二、对误差鲁棒的是最近邻，但它永不失败、只会静默撤错单。**
δ 从 1 ns 涨到 1 ms，最近邻命中只从 100.00% 掉到 96.71%。代价写在第二列：误选从 0% 升到
3.29%。26tok 的 L2 (`find_order_at_price_closest_time`) 正是无阈值最近邻，这就是
96.1435% 虚高的机制来源。

**三、建议的第二步形态：纳秒预测 + 最近邻 + 距离阈值 τ。**
τ 把「找不到」和「硬撤一单」之间的取舍变成显式参数：最近候选距离 > τ 时判 ambiguous，
不撤单。由 Δ_min 分布，**τ = 1 μs 是合理起点**，覆盖 97.38% 的目标且不会跳到干扰单上。
26tok 的病等价于 τ = ∞。

**四、这套数字仍是数据侧的误差敏感性，不是训练后成功率。**
真实 δ 的分布必须等 R7 训练后测。但本实验已足以否决一个设计分支（截断回退），并给出
替代形态与其参数，这正是「动代码前先测」要买到的东西。
