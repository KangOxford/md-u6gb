## 致命级（三条）

### V1 —— `real_book` 与 `gen_book` 是**两个不同程序**产出的

`inference_no_errcorr.py:2000-2006`：

```
m_seq_raw_eval, b_seq_pv_eval,   ->  real_msg, real_book    # LOBSTER 自己的 book
msgs_decoded,   l2_book_states,  ->  gen_msg,  gen_book     # jaxob 模拟器的 L2 输出
```

`extract_books.py` 把两者当同一种对象读。于是 spread / log_depth 比较的是
**LOBSTER 的 book 重建** vs **一个 100 槽 JAX order array 从 10 档快照种下去的回放**。
两个程序之间任何系统性差异都被记成模型的复合误差，**而且必然随 $m$ 增长**，
因为模拟器状态是单调发散的。

评审自己重算了 3136 对：

| | 真实 | 生成 |
|---|---|---|
| type-3 删除消息的平均 Δdepth | **−0.02** shares | **+6.60** shares |
| 每条 rollout 中删除的净贡献 | −4.4 | **+744.9** |
| 每条 rollout 净 depth 漂移 | −22.9 | **+1005.0** |

**一条删除消息净增加 6.6 股可见深度，不是消息分布偏差能产生的。**
它占了实测 depth 增长的 **74%**；而我在 R3 §3.2 归因的 event-mix 偏差
只有 +0.35 pp（生成 50.51% vs 真实 50.16%），约 140 股 = **14%**。
**R3 §3.2 的机理陈述在数量上是错的。**

模拟器至少四条路径会留下本该removed的流动性（`JaxOrderBookArrays.py:129-137/130/84-86/145-149`），
其中 `cancel_order` **只按 order id 匹配、不约束价格**。
而模型根本不输出 order id（`encoding.py:327-341` 是 `price_ref/size_ref/time_ref`），
由 pipeline 解析。评审在 5 万条生成消息里测到 **4.49% 带负 order id，
3.81% 落在 `[-21,-2]` —— 正是模拟器 init-id 命名空间**，
每一条都会撤掉一个无关价位的**播种单**。

**必须做的对照**：把**真实**的后续消息喂进**同一个** `sim_init`，产出第三条 `sim_real_book`，
然后报三条曲线：`KL(LOBSTER‖sim_real)`、`KL(LOBSTER‖sim_gen)`、`KL(sim_real‖sim_gen)`。
**只有最后一条是关于模型的陈述。** 若第一条已经上翘，则本文没有结果。

### V3 —— 度量对模型最大的失败失明，而 §3.3 那句最自信的话正是这个失明的产物

因为 $m$ 数的是**消息条数**，一个时钟慢 12 倍的模型在任何扩散量上都白拿一次赦免：

| m | $\sigma_{\rm true}$ | $\sigma_{\rm gen}$ | $t_{\rm real}$ | $t_{\rm gen}$ | vol真(tk/√s) | vol生成 | **比** |
|---|---|---|---|---|---|---|---|
| 250 | 3.218 | 3.350 | 0.674 s | 8.388 s | 3.921 | 1.157 | **0.295** |

**按秒算，模型的实现波动率是真实的 0.295 倍——波动率错 3.4 倍，方差错 11.5 倍。**
而我的度量给它 0.0248 nats，判「在地板上」。
**这正是我让评审去找的那种「大错特错却得分接近 0」的模型，而它就是当前基线。**

同样：平均到达间隔 **真实 4.07 ms vs 生成 82.03 ms（20.2×）**，
但 `log10` + z 标准化把它压成 **0.253 个标准差的位移**，报成 0.117 nats。
**RESULTS.md 里没有一句话告诉读者模型的时钟慢 20 倍。**
（中位数只差 2.4×，所以这是纯尾部效应，与已报告但未解读的尾部质量比 14.52 自洽。）

## 评审试图推翻但**没能推翻**的

1. **只用真实矩标准化是正确的，且没有造成方差盲点**：2× 方差的模型得 0.335 nats，0.5× 得 0.812，0.25× 得 3.169。**陷阱 T5 确实关闭了。**
2. **spread 趋势不是退化 rollout 造成的**：剔掉 98 条 spread 全程恒定的 rollout 后，斜率从 +0.2043 **升到** +0.2202。
3. 「中间价在地板上」在地板重标定后仍成立（0.0248 vs 修正地板 0.0240），但只差 3%。
4. **窗口重叠的担心不成立**：id 276 与 280 共享 0 条相同消息，相隔 4.2 秒；3136 个窗口实质不重叠。真正的样本量问题是 **20 个日 block**。

### 模式塌缩的修正器会怎样？评审的诚实回答：**九个里有五个会变好**

spread（前三值占 52.7%）、log_depth、imbalance、**log_dt（塌缩到众数反而修好 20× 均值偏差、降低 KL**，同时毁掉聚集与长记忆）、event_type/direction 都**抓不住**。
只有 delta_mid / delta_ticks 会被罚（0.5× sd ⇒ 0.81 nats）。
且在真实基线上**反向 KL 大于前向**（spread 0.2439 vs 0.2159；log_dt 0.2446 vs 0.1168），
说明塌缩不是当前的主要失败，**因此前向 KL 的保护在这份数据上尚未被检验**。
