# 132 个 Scaling-Law Checkpoints 的同分布验证损失

*S&P 500 LOB Mamba-3 队列 · valset_v1（30,720 样本）· 2026-07-30*

---

## 一句话结论

我们把 SP500 scaling-law 队列的全部 132 个 checkpoint（33 个 run 的 final-25% 窗口）放到 valset_v1 上逐一测完了 validation loss：每个 checkpoint 覆盖全部 30,720 个样本，逐样本 loss 落盘。数字揭示了三件此前不知道的事——同分布验证集比前向时移的 Jan-2026 测试集**更难**（所有规模上 Δ 为正）；这个差距**随模型变大而消失**（+0.055 → +0.005 nats）；held-out 意义下的「最优规模」**随评测分布移动**（valset 上是 120M，Jan-2026 上是 23M）。

## 为什么要补这把尺子

Rebuttal 里 SP500 队列的 held-out 证据一直只有一条轴：Jan-2026 test CE。它是前向时移评测——训练数据止于 2025 年 12 月，评测用 2026 年 1 月——所以模型的泛化能力和一个月的市场分布漂移被搅在同一个数字里。审稿人 pXiP 要求的 unconstrained refit 在这条轴上把 α 顶到了搜索区间上界，我们无法说清这是模型的问题还是尺子的问题。

valset_v1 正是为此准备的第二把尺子。它从训练语料的未消费区域取样（构造与零泄漏证明见 `VALSET_V1_REPORT.md`），与训练数据同分布、内容上是全域的均匀抽样、一次冻结永不改变。在它上面测同一批 checkpoint，时移的影响就被隔离出来了：同一个模型在两把尺子上的差，只能来自尺子本身。

选 132 个 checkpoint 而不是只测 33 个 run 终点，是为下一步拟合留后路。每个 run 的终点 D 与 N 几乎共线，只用终点拟合时 β 识别很弱（此前的 bootstrap 区间宽达 [0.17, 0.94]）；final-25% 窗口给每个 run 保留了 1 到 10 个不同 D 的 checkpoint，run 内部的 D 变异是 β 能被识别的前提。

## 怎么保证这些数字可信

三道防线。第一道是**覆盖**：不抽样。评测批大小被选成整除 30,720，顺序遍历下 drop_last 一个样本都不丢，132 个 checkpoint 各自完整跑过同样的 30,720 个样本。第二道是**实现同源**：前向代码就是训练代码（`s5e_mamba3` 的 `eval_step`），checkpoint 以 param-only 方式直读，数值上与训练曲线、与 Jan-2026 表用的是同一套实现，不存在第二份实现带来的口径漂移。第三道是**对齐验证**：两个不同 seed 的模型在逐样本 loss 上相关 0.9998，证明「第 i 个样本」在任何两次评测里都是同一个样本；把逐样本 loss 按 provenance 的 ticker 映射分组做方差分析得到 F=5.7（如果映射错位，F 会塌到 1 附近），证明 ticker 级聚合建立在正确的对应关系上。

两个口径都报。**micro** 是 30,720 个样本的等权平均，样本多的股票权重自然大，这与训练 loss 的构成一致，等长序列下它严格等于 token 级平均；**macro** 先在每只股票内部取平均、再对 487 只股票等权，这是 Jan-2026 表的口径。跨表比较只用 macro 对 macro。

评测跑在既有 allocation 的 4 张 GH200 上：每卡一个进程从共享队列抢 checkpoint（大模型优先），四轮批大小调优后大模型以 98–100% 利用率顶满硬件（350M 每个 52 分钟，200M 40 分钟），中小模型批大小放大至 16–32（批大小只受显存和整除性约束，对数值没有影响——评测是纯前向，模型里没有任何跨样本运算）。过程中有一个资源决策需要记录：泄漏行为学实验（§10）在 GPU 阶段被指令终止，为本评测让路；它的重跑排在本任务之后。

### 发现一：同分布验证集反而更难

132 个 checkpoint 无一例外，valset CE 高于自己的 Jan-2026 CE。直觉上前向时移应该更难——分布漂了——但数据说反了。解释藏在两把尺子的时间构成里：valset 按构造披露约 55% 的权重落在 2022 年，那是疫后高波动、高换手的一年；Jan-2026 只是一个相对平静的单月。市场状态对可预测性的影响，比一个月的分布漂移大得多。

这个结论对 rebuttal 有直接价值：它反驳了「Jan-2026 测试数字因分布漂移而系统性偏难、不能代表模型真实水平」的潜在质疑。事实恰好相反，前向单月比训练分布的时间混合更容易。

### 发现二：分布敏感性随规模消失

Δ 从最小模型的 +0.055 单调收敛到最大模型的 +0.005。小模型容量不够，学到的接近训练分布的「平均难度」，换一个权重结构就露馅；模型越大，对条件结构的刻画越细，重新加权对它的影响越小。这条单调收敛曲线本身就是「大模型泛化更稳」的直接证据，而且它是在两个真实评测分布之间测出来的，不依赖任何合成扰动。

### 发现三：「最优规模」跟着尺子走

valset 上 CE 最低的是 120M（macro 0.5971），46M 紧随其后；Jan-2026 上最低的是 23M。两条曲线都在 200M、350M 回升，这不是大模型变差了——350M 只消费了 17.8B token，而 6M 消费了 177.9B，回升是固定算力预算下 D 不足的必然结果。要点在于：**当有人问「多大的模型最好」时，答案取决于用哪把尺子量**。Rebuttal 里凡引用最优规模，必须绑定评测分布说话。

## 用这些数字时要知道的三件事

第一，比较两个 run 时不要拿两个 CI 去重叠。逐样本 loss 相关高达 0.9998，独立区间会把噪声放大三个数量级；正确做法是 per-sample paired bootstrap——同一批样本上两模型 loss 之差的分布。0.003 量级的 seed 间差异在 paired 口径下是清晰信号。全部 132 × 30,720 的逐样本 loss 都在盘上，这类计算随取随算。

第二，绝对值不要跨尺子混用。valset 与 Jan-2026 的分布差异是真实的（年度权重、单月对四年混合），做与全域同权重的结论时用逐样本 loss 按月重加权。

第三，本报告只交付评测数字与协议。valset 轴上的 unconstrained fit（α、β 重估）是下一步，132 点的 run 内 D 变异已经为它备好了原料。

## 拟合结果（2026-07-30 追加：Approach 3 与 Approach 2）

拟合完全复用 Jan-2026 轴的实现（`aramis/rebuttal_analysis.py` 的 `fit_model`/`select_protocol`/
`bootstrap_fits`/`isoflop_table`），两轴之间任何差异只能来自数据。协议同 `FIT_PROTOCOL.md`：
log-Huber(1e-3)、run 等权、bounds [0.1,2] 顶界必 flag、500 size 分层 run/seed bootstrap。

**Approach 3（additive surface，macro 口径）**：

| 轴 × 协议 | α 点估计 | α bootstrap 中位 [CI95] / 顶界占比 | β 点估计 [CI95] | E |
|---|---|---|---|---|
| valset, last25 (132/33) | **1.922 内点** | 1.936 [1.826, 2.000] / 34% | 1.337 [1.197, 2.000] | 0.5957 |
| Jan-2026, last25 (132/33) | 2.000 顶界 | — / 100% | 0.801 [0.527, 1.509] | 0.5552 |
| valset, endpoint (33/33) | 1.912 内点 | 1.942 [1.826, 2.000] / 33% | 1.726 [1.293, 2.000] | 0.5957 |
| Jan-2026, endpoint (33/33) | 2.000 顶界 | — / 100% | 1.408 | 0.5655 |

三条结论。第一，**α 的顶界病理是 Jan-2026 评测分布特有的**：同一批 checkpoint、同一套实现，
换到同分布 valset 后 α 点估计落到界内（1.92，宽界 [0.01,5] 诊断下不动），三分之二的 bootstrap
质量在界内（vs Jan 轴 500/500 顶界）。机制与主表自洽：valset 拉开了小模型端的 CE 断崖，
N 维动态范围更大（no-N 嵌套诊断 6.1× vs Jan 轴 4.23×）。严谨表述是「弱识别但多数质量在界内」，
CI 上端仍触界。第二，**β 移动但两轴 CI 重叠**（last25：1.337 [1.20,2.00] vs 0.801 [0.53,1.51]），
「换 held-out 分布后 β 实质改变」不获支持。第三，**E 干净分离**（0.5957 vs 0.5552，bootstrap
近零宽），把两个评测分布的难度差整体吸收进不可约项，与逐点 Δ>0 闭环。micro 口径的全部数字
与 macro 同构（`fits/valset_main_fits.csv`）。

**Approach 2（IsoFLOP）：结构性不可行，如实报告**。5 个 compute 切片 0 个满足可靠标准
（0 正曲率、0 bracketed），500 bootstrap draws 成功率 0。原因是数据几何而非实现：132 点只
覆盖每 run 的 final-25% C 窗口（跨度 ~1.33×），不同 size 的窗口在 C 轴上几乎不重叠，固定 C
切片无法穿过 ≥5 个 size。valset 轴要做 Approach 2 需要补评每 run 的早期 checkpoint（全轨迹），
这是后续可选扩展。产物：`fits/valset_isoflop_*`。
