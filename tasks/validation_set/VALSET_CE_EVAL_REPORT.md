# 132 个 Scaling-Law Checkpoints 的同分布验证损失

*S&P 500 LOB Mamba-3 队列 · valset_v1（30,720 样本）· 2026-07-30；Jan-2026 shuffle 第三把尺子 2026-07-31 追加*

---

## 一句话结论

我们把 SP500 scaling-law 队列的全部 132 个 checkpoint（33 个 run 的 final-25% 窗口）放到 valset_v1 上逐一测完了 validation loss：每个 checkpoint 覆盖全部 30,720 个样本，逐样本 loss 落盘。数字揭示了三件此前不知道的事：同分布验证集比前向时移的 Jan-2026 测试集**更难**（所有规模上 Δ 为正）；这个差距**随模型变大而消失**（+0.055 → +0.005 nats）；held-out 意义下的「最优规模」**随评测分布移动**（valset 上是 120M，Jan-2026 上是 23M）。

2026-07-31 追加的第三把尺子（Jan-2026 shuffle，同月同数据、仅把「每股等窗且集中月初」改为「全月随机」）把上面第三条从现象推进到了归因：**α 的顶界病理由现行口径的采样设计造成，而非 Jan-2026 这个月的分布特殊**。同一批 checkpoint 在 shuffle 版上的 α 顶界占比是 35.6%，与完全不同数据集的 valset（34.0%）几乎无法区分，而现行口径是 100%；最优规模也随之从 23M 回到 120M。详见「第三把尺子」节。

## 为什么要补这把尺子

Rebuttal 里 SP500 队列的 held-out 证据一直只有一条轴：Jan-2026 test CE。它是前向时移评测——训练数据止于 2025 年 12 月，评测用 2026 年 1 月——所以模型的泛化能力和一个月的市场分布漂移被搅在同一个数字里。审稿人 pXiP 要求的 unconstrained refit 在这条轴上把 α 顶到了搜索区间上界，我们无法说清这是模型的问题还是尺子的问题。

valset_v1 正是为此准备的第二把尺子。它从训练语料的未消费区域取样（构造与零泄漏证明见 `VALSET_V1_REPORT.md`），与训练数据同分布、内容上是全域的均匀抽样、一次冻结永不改变。在它上面测同一批 checkpoint，时移的影响就被隔离出来了：同一个模型在两把尺子上的差，只能来自尺子本身。

选 132 个 checkpoint 而不是只测 33 个 run 终点，是为下一步拟合留后路。每个 run 的终点 D 与 N 几乎共线，只用终点拟合时 β 识别很弱（此前的 bootstrap 区间宽达 [0.17, 0.94]）；final-25% 窗口给每个 run 保留了 1 到 10 个不同 D 的 checkpoint，run 内部的 D 变异是 β 能被识别的前提。

## 怎么保证这些数字可信

三道防线。第一道是**覆盖**：不抽样。评测批大小被选成整除 30,720，顺序遍历下 drop_last 一个样本都不丢，132 个 checkpoint 各自完整跑过同样的 30,720 个样本。第二道是**实现同源**：前向代码就是训练代码（`s5e_mamba3` 的 `eval_step`），checkpoint 以 param-only 方式直读，数值上与训练曲线、与 Jan-2026 表用的是同一套实现，不存在第二份实现带来的口径漂移。第三道是**对齐验证**：两个不同 seed 的模型在逐样本 loss 上相关 0.9998，证明「第 i 个样本」在任何两次评测里都是同一个样本；把逐样本 loss 按 provenance 的 ticker 映射分组做方差分析得到 F=5.7（如果映射错位，F 会塌到 1 附近），证明 ticker 级聚合建立在正确的对应关系上。

两个口径都报。**micro** 是 30,720 个样本的等权平均，样本多的股票权重自然大，这与训练 loss 的构成一致，等长序列下它严格等于 token 级平均；**macro** 先在每只股票内部取平均、再对 487 只股票等权，这是 Jan-2026 表的口径。跨表比较只用 macro 对 macro。

评测跑在既有 allocation 的 4 张 GH200 上：每卡一个进程从共享队列抢 checkpoint（大模型优先），四轮批大小调优后大模型以 98–100% 利用率顶满硬件（350M 每个 52 分钟，200M 40 分钟），中小模型批大小放大至 16–32（批大小只受显存和整除性约束，对数值没有影响——评测是纯前向，模型里没有任何跨样本运算）。过程中有一个资源决策需要记录：泄漏行为学实验（§10）在 GPU 阶段被指令终止，为本评测让路；它的重跑排在本任务之后。

### 发现一：同分布验证集反而更难

132 个 checkpoint 无一例外，valset CE 高于自己的 Jan-2026 CE。直觉上前向时移应该更难——分布漂了——但数据说反了。解释藏在两把尺子的时间构成里：valset 按构造披露约 55% 的权重落在 2022 年，那是疫后高波动、高换手的一年；Jan-2026 只是一个相对平静的单月。市场状态对可预测性的影响，比一个月的分布漂移大得多。

这个结论对 rebuttal 有直接价值：它反驳了「Jan-2026 测试数字因分布漂移而系统性偏难、不能代表模型真实水平」的潜在质疑。事实恰好相反，前向单月比训练分布的时间混合更容易。

### 发现二：分布敏感性随规模消失

Δ 从最小模型的 +0.055 单调收敛到最大模型的 +0.005。小模型容量不够，学到的接近训练分布的「平均难度」，换一个权重结构就露馅；模型越大，对条件结构的刻画越细，重新加权对它的影响越小。这条单调收敛曲线本身就是「大模型泛化更稳」的直接证据，而且它是在两个真实评测分布之间测出来的，不依赖任何合成扰动。

### 发现三：「最优规模」跟着尺子走

valset 上 CE 最低的是 120M（macro 0.5971），46M 紧随其后；Jan-2026 上最低的是 23M。两条曲线都在 200M、350M 回升，这不是大模型变差了——350M 只消费了 17.8B token，而 6M 消费了 177.9B，回升是固定算力预算下 D 不足的必然结果。要点在于：**当有人问「多大的模型最好」时，答案取决于用哪把尺子量**。Rebuttal 里凡引用最优规模，必须绑定评测分布说话。

## 用这些数字时要知道的三件事

第一，比较两个 run 时不要拿两个 CI 去重叠。逐样本 loss 相关高达 0.9998，独立区间会把噪声放大三个数量级；正确做法是 per-sample paired bootstrap——同一批样本上两模型 loss 之差的分布。0.003 量级的 seed 间差异在 paired 口径下是清晰信号。全部 132 × 30,720 的逐样本 loss 都在盘上，这类计算随取随算。

第二，绝对值不要跨尺子混用。valset 与 Jan-2026 的分布差异是真实的（年度权重、单月对四年混合），做与全域同权重的结论时用逐样本 loss 按月重加权。

第三，本报告只交付评测数字与协议。valset 轴上的 unconstrained fit（α、β 重估）是下一步，132 点的 run 内 D 变异已经为它备好了原料。

## 第三把尺子：Jan-2026 shuffle（2026-07-31 追加）

valset 轴已经证明 α 的顶界病理不是模型的问题，但它留下一个可被反驳的缺口：valset 是**另一个数据集**（2022–2025 四年混合），审稿人完全可以说「换了数据集当然不一样，这说明不了 Jan-2026 那把尺子有毛病」。补这把尺子就是为了堵这个缺口。Jan-2026 shuffle 用的是**同一个月、同一批原始数据、同一套前向实现**，唯一改动是采样设计：现行口径每股等窗且窗口集中在月初，shuffle 版则从全月窗口池里完全随机抽取，保留自然分布。如果仅此一改就让病理消失，那病灶就只能在采样设计本身。

构造与验证。全月池按训练 dataloader 的枚举序（ticker 字母序 → 文件名序 → 文件内窗口序，每文件 `floor(rows/500)` 个不重叠 500-msg 窗口）展开得 7,507,307 个窗口，固定 `seed=20260131` 全排列后取前 30,720 个，覆盖 487 只股票（Jan-2026 实际缺 BAC）。同一批 132 个 checkpoint、同一份 `valset_ce_eval.py`，逐样本 loss 全部落盘。ticker 到 sample 的逐位对齐用单因素 ANOVA 加阴性对照复核：对齐时 F 落在 24.9 至 31.9，把 ticker 标签随机打乱后 F 塌到 0.87 至 1.12，证明 macro 聚合建立在正确对应关系上（与 valset 的 F=5.7 同法；这里 F 显著更高，因为单月数据的 ticker 间差异不被四年时间混合稀释）。

### 发现四：现行口径把最优规模左移，是偏差结构而非噪声

四个口径里有三个（valset macro、Jan-shuffle macro、Jan-shuffle micro）把最低点放在 120M，唯独现行的 Jan-2026 ticker-等权口径给出 23M。为什么偏偏是它，答案在最后两列的形状对比里。`valset − shuffle` 是一个近乎常数的偏移：除 0p2M 的 +0.0930 外，1M 到 350M 全部落在 +0.0720 至 +0.0754，跨两个数量级只漂 0.003。常数偏移会整体抬高曲线，但不改变曲线最低点的位置。`Jan现行 − shuffle` 则不是常数：它在小模型端从 +0.0398 递减到 6M 的谷底 +0.0253，随后在大模型端从 23M 的 +0.0361 单调爬升到 350M 的 +0.0669，接近翻倍。正是大模型端这段单调递增把曲线尾部往上掰，使最低点从 120M 左移到 23M。需要说清的是，这条差值曲线整体呈 U 形而非全程单调，小模型端的非单调不影响结论，因为移动最优点的只是大模型端那一段。由于两边 macro 都是 487 只股票等权，加权维度已被控住，这个差值是纯粹的时段效应（集中月初对全月随机）。

| valset, endpoint (33/33) | 1.912 内点 | 1.942 [1.826, 2.000] / 32.6% | 1.726 [1.293, 2.000] | 0.5957 |
| Jan-2026 现行, endpoint (33/33) | 2.000 顶界 | — / **100%** | 1.408 | 0.5655 |

关键不在于「Jan-shuffle 轴上顶界消失了」，而在于**它的顶界占比与 valset 几乎无法区分**：35.6% 对 34.0%（last25），34.8% 对 32.6%（endpoint），而现行口径是 100%。Jan-shuffle 与现行口径共享同一个月的同一批数据，valset 则是完全不同的数据集，可拟合行为上 Jan-shuffle 站到了 valset 那一侧。这意味着划分「病理与正常」的界线不是数据取自哪个分布，而是采样设计，现行口径的 100% 顶界因此无法用「Jan-2026 这个月特殊」来辩护。严谨表述与 valset 节保持一致：Jan-shuffle 轴同样是弱识别，约三分之二的 bootstrap 质量在界内，CI 上端仍触界 2.000。β 的走向同方向，Jan-shuffle 的 1.405 [1.266, 1.881]（顶界占比仅 1.8%）与 valset 的 1.337 [1.197, 2.000] CI 重叠良好，两者都明显高于现行口径的 0.801 [0.527, 1.509]。E 三者干净分离（0.5234 对 0.5552/0.5655 对 0.5957，bootstrap 近零宽），把三个评测分布的难度差整体吸收进不可约项。500 draws 全部成功，零失败。

### micro 口径在这把尺子上不与 macro 同构，原因是 ticker 集中度

valset 节曾写「micro 口径的全部数字与 macro 同构」，这句话在 Jan-shuffle 轴上不成立，必须如实分开报告。Jan-shuffle 的 micro 侧 α 顶界占比达到 50.6%（last25）与 51.4%（endpoint），中位数几乎贴着上界（1.9994 / 1.9998），远高于自身 macro 侧的 35.6% / 34.8%；而 valset 的 micro 与 macro 只差约 3 个百分点（37.0% / 35.6% 对 34.0% / 32.6%）。机制是样本在股票间的集中度，用 Kish 有效样本量 `n_eff = (Σw)² / Σw²` 量化：valset 的 487 只股票折合 164.6 个等效单元（33.8%，单只最高占 2.6%），Jan-shuffle 只折合 74.6 个（15.3%，单只最高占 6.7%，最大股票 2,053 个窗口对最小 4 个）。自然分布下少数高流动性股票主导了 micro 平均，N 维的有效信息被压缩，识别随之变弱；macro 强制 487 只等权后集中度被消除，顶界占比回落到与 valset 齐平。这也解释了主表里 micro 系统性低于 macro（350M 差 0.028，0p2M 差 0.066）：窗口多的高流动性股票本身更好预测。

### 独立复现（2026-07-31 追加）

这一节的拟合被两条互不知情的代码路径各算了一遍：一条是本节原有的 `jan_shuffle_fit_approach3.py`，另一条是另一会话为「任意评测轴」写的泛化版 `axis_fit_approach3.py`（把 master 表、主口径、输出目录提成参数，拟合仍全量复用 `rebuttal_analysis`）。两者从同一批 132 个结果出发，α 分别为 1.886196 / 1.886195（macro endpoint）、1.892724 / 1.892728（macro last25）、1.951522 / 1.951531（micro endpoint）、1.962709 / 1.962699（micro last25），β 与 E 同样一致，最大偏差 1e-5，属优化器收敛容差量级。这不是同一段代码跑两次，而是两份独立实现给出同一答案，可以排除数据装载、协议选择、口径映射三个环节的实现错误。

## Approach 2 解锁：补评 124 个早期 checkpoint 后的 IsoFLOP（2026-07-31 追加）

上面 Approach 2 那一段的结论是「结构性不可行」，根因写得很清楚：132 点只覆盖每个 run 的
final-25% 窗口，每条 chain 在 C 轴上的跨度中位只有约 1.3 倍，等于一条短线头，固定 C 的竖切线
扎下去只能戳中同量级 N 的一两条链，凑不出抛物线。这是数据覆盖的问题，不是拟合技巧能补的，
所以解法只有一个：把每条 chain 在 C 轴上拉长。

124 个早期 checkpoint 的 valset CE 已于 2026-07-31 补评完毕（job 5827830 的 attach step，
4×GH200，124/124，三道闸门全过），与原 132 点合并得到 **256 点全轨迹**。两批坐标零重叠
（label 与 (size, seed, step) 交集均为 0），dmon 实测 FLOPs 256/256 全部 join 上。
补评后每条 chain 的点数升到中位 8 个，C 跨度呈双峰：78M 到 350M 这些大模型档因为补到了
step 170 至 350 的极早期点，跨度达到 44 到 216 倍，而 4M 到 14M 的小模型档补得少、跨度仍在
1.2 到 1.6 倍。这个不均匀并不妨碍 IsoFLOP，因为竖线要穿的是不同 N 而非同一条链：
大模型的早期点正好落进小模型的 C 区间，12 个 C target 上每个都覆盖 4 到 9 个不同的 N，
**12/12 切片满足可拟合条件，而 132 点时代是 0/5**。

结果是 11/12 个切片拟出正曲率且被数据包夹的谷底（唯一失败的 C=2.35e18 抛物线开口向下，
如实计入分母）。**但 slope 对切片纳入标准高度敏感，只报单一数字会把脆弱结论包装成精确结论**：

| 纳入标准 | 切片数 | slope |
|---|---:|---:|
| 全部 bracketed（脚本默认口径） | 11 | 0.4652 |
| 左右各 ≥2 个**不同 size** 包夹 | 5 | 0.4212 |
| 排除最低 C 切片（C ≥ 3e18） | 10 | **0.2850** |
| 两条件同时满足 | 5 | 0.4212 |

敏感性的来源是最低 C 那个切片：它的 N\* = 4M 落在 0p2M（2.6M）与 23M 之间的 size 空隙里属于外推，
L\* = 0.9607 比其余切片高约 0.36 nats，剔除它 slope 立刻从 0.465 掉到 0.285。需要说明的是，
脚本自带的「包夹」判据按点数计，会把同一 size 的三个 seed 算作三个左包夹点，实质上 N\* 左侧
仍只有一个 size 支撑，所以上表另算了一份按不同 size 计的严格判据。

正确的表述因此是：**实测 slope 落在 0.285 到 0.465 之间，取决于切片纳入标准**。这个区间与
同一队列 surface-implied 的 0.309（last25）与 0.491（termination）重叠，方向也一致，
held-out 口径下的 compute-optimal 分配远比 train 面的 0.783 更偏数据端，与 Jan-2026 轴
held-out 的 0.294 同向。挑其中一个数字去宣称与某个 surface-implied 值精确吻合，数据不支持。

图与产物：`valset_eval/fits_valset256/figures/isoflop_valset_all256_<stamp>_{parabolas,summary}.png`
（parabolas 每个 C target 一个面板，散点标 chain、黑虚线为抛物线、红虚线为 N\*；summary 左为
横截面点云加 valley 序列与幂律线，右为各切片插值 L 按模型规模着色）、同名 `_results.json`、
`fits_valset256/isoflop256_slope_robustness.{csv,md}` 与 `isoflop256_slice_detail.csv`（上表的可复现产物）、
256 点输入表 `fits_valset256/valset_fit_ready_all256_<stamp>.csv`。
复现：`build_valset256_fit_ready.py` 建表（含 macro 重建与 ANOVA 对齐闸门，F 5.9 至 7.5 对打乱对照约 1.0）
