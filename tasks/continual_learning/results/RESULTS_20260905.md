## 3. Item 3 — the discriminating null, and its floor

k = 3 (leaving 4 seeds to estimate the nuisances), 60 draws, horizon 50.

| ticker | ρ | ρ partialled | fraction kept |
|---|---|---|---|
| AMD | 0.362±0.027 | 0.315±0.032 | 0.87 |
| AMZN | 0.334±0.032 | 0.284±0.035 | 0.85 |
| GOOG | 0.253±0.045 | 0.232±0.050 | 0.92 |
| INTC | 0.388±0.036 | 0.349±0.044 | 0.90 |
| JPM | 0.382±0.036 | 0.321±0.043 | 0.84 |
| META | 0.364±0.035 | 0.311±0.039 | 0.85 |
| MSFT | 0.329±0.031 | 0.282±0.037 | 0.86 |
| NFLX | 0.431±0.024 | 0.384±0.025 | 0.89 |

**The floor.** A synthetic score built to be *entirely* dispersion — rollouts centred on
the truth, differing only in a per-context width, so nothing about being wrong is present —
keeps **0.48** under the identical procedure at 10 seeds. The honest answer for that score
is 0; it is not 0 because the nuisance is estimated from held-out seeds and a noisy proxy
under-removes. The floor falls as the proxy improves: **0.48 at 10 seeds, 0.37 at 12**, so
it must be measured at the seed count in use and never carried over from another.

So the reading is **"0.87 against a 0.48 floor"**. The conclusion (a real conditional signal
survives) stands; the margin is roughly half what "0.87 of it survives" implies. This is the
same error shape as reading a stratified null of 0.10 as zero.

## 4. Item 4 — `num_errors`

Source, `.../crps-return-alignment-20260808/src/mid_training/return_alignment/gen_driver.py`:

```python
# count errors when the message does not change the (visible) book state
num_errors = (l2_book_states[1:] == l2_book_states[:-1]).all(axis=1).sum()
```

The comment says errors; the expression counts **generated messages that left the visible
L2 book unchanged**, out of `--n_gen_msgs` 250.

| ticker | mean | fraction of 250 | per-context range |
|---|---|---|---|
| AMD | 179.5 | 0.718 | 0.244–0.996 |
| AMZN | 163.6 | 0.655 | 0.248–0.996 |
| GOOG | 156.1 | 0.624 | 0.160–0.996 |
| INTC | 93.5 | 0.374 | 0.012–0.996 |
| JPM | 173.2 | 0.693 | 0.264–0.988 |
| META | 190.9 | 0.764 | 0.252–0.996 |
| MSFT | 171.0 | 0.684 | 0.284–0.996 |
| NFLX | 85.0 | 0.340 | 0.012–0.996 |

**Pooled, 60.6% of every generated rollout does nothing to the visible book**, ranging
34.0%–76.4% across tickers. That is a fact about generation and needs no join.

**What cannot be verified.** The log prints 11 batches of 48 = **528 slots for 500
contexts**. The 28 surplus are neither a wrap of the first 28 nor of the last 28 — checked
in all 8 tickers, both comparisons false. So the position-to-context mapping is
unestablished, and the audit's per-context correlations (reliability 0.60–0.78, sign-flip
between tickers) cannot be reproduced without it. **Marked insufficient, not refuted**: the
join may well be recoverable from the batch construction in `gen_driver.py`, which has not
been read for this purpose.

## 5. Item 5 — the `fidelity.py` completion criterion

**A correction to what was pushed in `49694537`.** That commit and `PLAN.md` §0.6 state that
`fidelity.py` "exits 0 having printed only a header row". Re-run without a pipe:

```
REAL exit code (no pipe): 1
stdout lines: 1     stderr lines: 26
FileNotFoundError: .../data_cond/AMD_2026-01-07_orderbook_real_id_27578.csv not found.
```

The exception propagates and Python exits **1**. The `exit=0` originally reported was
`tail`'s exit code, read as `$?` after a pipe. ~~The tool reports success on a failed run.~~

**The narrower claim is real and the guard is warranted.** A window whose report lacks both
arms is skipped by a `continue`, so a run in which *every* window is skipped without raising
printed a header, summarised over empty lists, and returned 0 — verified by stubbing
`window_report` to return `{}`: 1 window discovered, 0 scored, `return 0`. Patched:

```python
n_scored = len(rows["real"]) + len(rows["gen"])
if n_scored == 0:
    print(f"FAILED: {len(windows)} window(s) discovered, 0 scored. "
          f"A report with no rows is not a result.")
    return 2
```

Verified: the stubbed case now returns **2**. The edit is in the `sigma-0` working tree at
`/lus/lfs1aip2/projects/public/u6gb/sigma-0/src/post_training/heuristic_learning/fidelity.py`
and is **not yet committed there** — `sigma-0` is a separate private repository whose commits
require the `junming` identity and a check of the PR#60 stack top.

**What does not change**: `data_cond/` is still absent from all 80 members, so M1 still
cannot run on the existing archive. That finding rested on the `FileNotFoundError`, not on
the exit code.
