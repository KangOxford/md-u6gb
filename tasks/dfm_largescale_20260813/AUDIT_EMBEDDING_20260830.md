# 审计二：embedding——AR 从不需要的性质，DFM 拿来当地基

应用户问（2026-08-30）：「讲讲我这里的 embedding，我怀疑这里多少有点问题。」
结论先行：**怀疑成立，且这是三个审计对象里病因最清楚的一个。这套 embedding
是按 AR next-token 目标训出来的——那个目标从头到尾没要求过它具备度量几何；
DFM 却在三个位置把它当有几何的空间用。已量出的三组数字（几何≈随机表、
一个向量 14 个角色、度量失效级联）都指向同一句话：需求不对称。**

## 1. 它是什么、在哪些位置被使用

`nn.Embed(vocab=2112, d_model=1024)`，预训练冻结。DFM 修正器里三个角色：

| 角色 | 位置 | 对几何的需求 |
|---|---|---|
| (a) 主干输入 | `message_encoder(x_m)` | 无——AR 靠上下文条件，查表即可 |
| (b) 残差输入 | `h_embed = encoder(x_m)`（lob_seq_model.py:702-704） | 中——修正方向从它投影出来 |
| (c) corruption 度量 | `lob/train/dfm.py` 的距离矩阵（**原版**） | **高——路径的整个形状建在它上面** |

角色 (a) 是预训练唯一优化过的。(b)(c) 是 post-training 新加的负担。

## 2. 三组已量出的数字

### 2.1 几何接近随机（角色 c 的死因）

- coupling ratio **6.69**，随机表 7.13，1-D 流形 0.38——embedding 的
  邻接结构与随机初始化几乎不可区分（PR comment 5468025736 的主证据）。
- 序数性（嵌入距离与数值距离的秩相关）：`price` 0.240、`size` 0.264、
  **`time` 0.073**。1.0 = 模型知道 500 比 501 更接近 499；0 = 没有这个信息。
- 直接后果：embedding-L2 度量下 corruption path 的 retention 只从 3.3% 走到
  10.1%（应为 ~0%→~100%）——**论文 Eq.(6) 的 cosine schedule 在这个空间里
  根本展不开**，于是被迫换 field 度量 + beta_max 从 10 改到 14/70/248.68
  （"beta_max is not portable between metrics"，dfm.py 自注）——
  每一步都是对论文 path 的又一次偏离（comment 5468026114 的四轴）。

### 2.2 一个向量 14 个角色（角色 a 的隐性成本、b 的天花板）

`place_probe.json` 的复用计数：`time` 块 1000 token 被 **14 个 offset** 共用
（price 6、size_digit 4）。token「500」同时要表示 500 秒、5 亿纳秒、500 纳秒
——真实跨度六个数量级，共享一个 1024 维向量。已定罪的后果：

- time 块占 teacher-forced 总损失 **76.6%**；两个位置（delta_t_ns 个位/中位）
  吃掉 53.1%，acc 0.281/0.456；
- 高位数字写进低位的混淆 z = **+33.32**（置换零假设）；
- 复用计数排序与序数性排序、与损失占比排序**三向一致**（独立测量）。

### 2.3 B7b 的修补是加性的，上限已量出

B7b 给 h_embed 加 26 个逐位置偏移（`dfm_offset_table`，加法）：同一 token 的
14 个角色仍共享同一个基向量，角色差异只能是**平移**。它买到了
teacher-forced −0.53 与时间戳单调率 56%→83%，买不到 5 字段计数（四格两月
0/5，comment 5467999663）。**加性修补的上限就到这里。**

## 3. 病根：需求不对称，而不是「embedding 训坏了」

AR 预训练的损失从不惩罚「嵌入距离与数值距离无关」——上下文条件下的
softmax 只要类别可分即可。**这套 embedding 对它的本职（角色 a）没有毛病。**
毛病在 post-training 把它临时提拔成度量空间（角色 c）与修正基（角色 b），
却没有任何一步训练让它具备这些性质。论文的 Algorithm 1 预设
「嵌入度量有语义几何」——那是在别的域里恰好成立的性质，这里不成立。

## 4. 对修复设计的含义

1. **角色 c 已经绕开**（field 度量），代价是离开论文 path——这是 Line B
   健康检查存在的原因，不必再动。
2. **角色 b 的修法在 P 的审计里**（AUDIT_P_MATRIX §3）：给残差换上下文输入、
   换掉 LN——比给 embedding 动手术便宜且正交。
3. **不要试图「修 embedding」**（重训 embedding = 动基座模型 = Line C 的
   拆词表方案的一半成本，却不解决进位边界）。若走到那一步，直接走
   Line C 的单 token 数值编码——一次把复用与进位两个病都治掉。
4. R2（p0=draft 训练）与 embedding 正交：corruption 已用 field 度量，
   语料对齐不经过 embedding 几何。R2 保留 B7b 的 offset 表（它的
   teacher-forced 收益是真的）。
