这两点是全文技术含量最高的地方，也是公众号转述得最糙的地方。
内容来自论文 §2.2、§3、§4。

## 一、Luna-Codec：为什么要把语义"钉"在第一层码本

### 规格

| 项 | 值 |
|---|---|
| 采样率 | 24 kHz |
| 帧率 | **25 Hz**（每帧 40 ms） |
| 码本数 $Q$ | **8** |
| 每码本条目数 | 2048 |
| token 率 | 25 × 8 = **200 token/秒** |
| 有效码率 | 2.2 kbps |
| 结构 | 步进因果卷积编码器 + 轻量因果 Transformer 瓶颈；解码器镜像，**逐帧同步**重建 |
| 训练数据 | 40 万小时中英日韩 |

**"因果"很重要**：解码器是因果的，所以合成音频能以每帧粒度往外送，
这是 Realtime 能流式播放的前提。

### 要解决的问题

RVQ 的层次是"逐层编码残差"，如果直接做端到端重构训练，会出现一个坏性质：

```
纯声学 RVQ 的自发行为：
  CB1 ─┐
  CB2 ─┤ 前几层【抢着】去编码精细频谱细节
  CB3 ─┘   （因为那是降低重构误差最快的方向）
  ...
  CB8

后果：token 序列变得【很难从文本预测】
      文本"你好"能告诉你说的是什么，但告诉不了你第 3 帧的高频谐波长什么样
      而 CB1 里塞满了这种东西
```

论文原话：*"Purely acoustic RVQ tokens front-load fine spectral detail into early
codebooks, which makes the token sequence unnecessarily hard to predict from text."*

注意 **unnecessarily**（不必要地）这个词——难度不是任务固有的，是 tokenizer 训练方式
自己造出来的。

### 解法：给 CB1 加一个语义蒸馏 loss

```
                      ┌─────────────────────────────────────┐
   波形 ──► encoder ──►│ CB1 ◄── 蒸馏 WavLM 的帧级表征        │  语言/字音骨架
                      │ CB2 ┐                               │
                      │ CB3 │                               │
                      │  :  ├── 自由学习，无额外约束           │  音色 / 韵律 / 声道 / 情绪
                      │ CB8 ┘                               │
                      └─────────────────────────────────────┘
                          深度轴 ≈ 从"语言信息"到"声学信息"有序
```

**WavLM** 是微软的自监督语音表征模型，它的中间层表征已知富含音素/语言信息。
拿它的帧级表征去监督 CB1，等于**强行规定 CB1 承载语言内容**，
剩下 CB2–CB8 才去捕获音色、韵律细节、通道特性。

结果是**深度轴大致按"语言 → 声学"排序**，这带来一个关键性质：
网格从文本可预测（因为最重要的那一层就是语义），同时保留了信号的全部声学细节。

### 完整训练配方

时域 + 多尺度 mel 域重构 loss、VQ commitment loss、
多周期 + 多分辨率 STFT 判别器的对抗训练，**外加** CB1 蒸馏 loss。
Quantizer dropout 提供码率可伸缩性（推理时可以少用几层码本换更低码率）。

### 一个被公众号跳过的设计立场

主流 LLM-TTS（CosyVoice、GLM-TTS、Seed-TTS、Qwen-Audio）走的是**两段式**：
语言模型预测**低码率语义 token**，然后交给一个独立的 flow-matching / diffusion
detokenizer 去渲染声学细节。

Luna-TTS 明确反对这个切分，理由是它制造了**语义–声学鸿沟**：

> "the language model never sees, and can never optimize for, the acoustic detail
> that determines speaker fidelity and expressiveness"

（语言模型永远看不到、也永远无法优化决定音色保真度和表现力的声学细节。）

所以 Luna-TTS **直接建模完整的多码本网格**，让单个生成阶段拥有全部信息，
codec 解码器退化成一个确定性的轻量映射。

```
主流两段式:  文本 ──► LM ──► 语义token ──► flow-matching 渲染器 ──► 波形
                            ↑ LM 到此为止，看不见后面的声学决策

Luna-TTS:    文本 ──► 扩散LM ──► 完整 T×8 声学网格 ──► codec 解码（确定性）──► 波形
                            ↑ 一个阶段拥有全部信息，RL 也能直接优化到声学层面
```

这个立场直接影响了 RL 那一节：因为模型自己就产出最终声学 token，
所以 WER / SIM 这类"要解码成波形才能算"的奖励可以直接回传到生成模型上。

## 二、把 GRPO 迁到非自回归掩码扩散上

### 先说清楚难点

**GRPO**（Group Relative Policy Optimization）是 DeepSeekMath 提出的 RL 后训练方法：
对同一个 prompt 采 $G$ 个候选，用组内均值和标准差把奖励标准化成优势
（省掉了 PPO 的 value network），再用 PPO 式的裁剪代理目标更新。

**它在 AR 模型上很自然**，因为 AR 的输出概率有链式分解：

```
AR:   log p(x) = Σ_t log p(x_t | x_<t)          ← 每个 token 有明确的、可算的条件概率
                                                  policy ratio 逐 token 算就行
```

**掩码扩散没有这个分解。** 它通过多步迭代并行去噪产出网格，
输出的边际似然 $p_\theta(\bm{X}|\bm{c})$ 需要对所有可能的解掩顺序求和，**不可解**。

之前的 dLLM RL 工作（论文引 [59]）用**一步 mean-field 代理**去近似这个难解的似然。
Luna-TTS 不走这条路。

### 解法：在"实际走过的去噪轨迹"上定义 ratio

核心思路一句话：**不要试图去算最终序列的概率，而是记录生成过程中实际做出的每一个
token 决策，在这些决策上算 ratio。**

```
生成一条候选的过程 = 一条轨迹 τ

  步 k=0:  状态 s_0  →  解码器选出要解掩的位置集 M_0  →  采样出这些位置的值 a_0
  步 k=1:  状态 s_1  →  位置集 M_1                    →  值 a_1
   ⋮
  步 k=S-1

  τ = { (s_k, M_k, a_k) }_{k=0}^{S-1}
```

给定 $M_k$（哪些位置在这一步被解掩），token 分布可以**因子化**：

```
π_θ(a_k | c, s_k, M_k) = ∏_{p ∈ M_k} π_θ(a_{k,p} | c, s_k, p)
```

于是逐动作的对数比与重要性比就有了定义：

```
Δ_{g,i,j}(θ) = log π_θ(a_{g,i,j} | z_{g,i,j}) − log π_old(a_{g,i,j} | z_{g,i,j})
r_{g,i,j}(θ) = exp(Δ_{g,i,j}(θ))

  g = prompt 组   i = 候选轨迹   j = 已提交的 token 动作
  z = 对应的条件 + 去噪状态 + 位置
```

**两个精细但要命的设计决定：**

| 决定 | 内容 | 为什么必须这样 |
|---|---|---|
| **只对 token 决策做 RL，不对"选哪些位置解掩"做 RL** | 位置序列 $M_k$ 被当作**已实现的条件**，不是要优化的对象 | 保持与模型原生解掩过程兼容。要联合优化解掩顺序，就得引入一个显式的随机位置策略（论文把它列进 Future Work） |
| **rollout 和 replay 必须在【同一个有效策略族】下算概率** | $\pi_\theta$ 定义为**施加了解码器全部变换之后**的分布：合法性约束、top-$k$ 截断、温度、**以及 CFG** | 论文原话："ratios computed from the untransformed model distribution need not correspond to the distribution that generated the speech tokens"。用原始模型分布算 ratio，算的就不是真正产生这些 token 的那个分布 |

> 第二条是最容易踩的坑，也是本仓库熟悉的一类问题：**采样时用了一堆变换，
> 记账时却拿没变换过的分布去算**——两边不是同一个东西，ratio 从定义上就错了。
> CFG 尤其隐蔽，因为它是"两路前向的线性组合"，不是模型的原生输出。

### 优势与目标函数

组内标准化（这就是 GRPO 的 G）：

```
A_{g,i} = ( R_{g,i} − μ_g ) / ( max(σ_g, σ_min) + ε )
```

$\mu_g,\sigma_g$ 是该 prompt 组内 $G\ge 2$ 个候选的奖励均值与样本标准差。
**一条轨迹里所有 token 决策共享这一个句子级优势。**

小批量目标：

```
L_RL = (1/|B|) Σ_{(g,i)∈B} (1/n_{g,i}) Σ_{j=1}^{n_{g,i}} ℓ_clip( r_{g,i,j}, A_{g,i} )
```

其中 $\ell_{\text{clip}}$ 是 PPO 式裁剪代理，$n_{g,i}$ 是该轨迹被回放的 token 决策数。

三个值得注意的实现选择：

1. **在 token 层面施加代理，而不是把一条轨迹的 ratio 连乘。**
   并行决策连乘会让方差爆炸（一步可能提交上百个位置）。
2. **按 utterance 归一化**（除以 $n_{g,i}$），防止长句子获得不成比例的权重。
3. **目标对已记录的动作是可加的**，所以 replay 可以按去噪状态分解，
   用来控制显存，而不改变归一化。

### 奖励：字典序，不是加权和

每条生成的波形由两个**冻结**的模型打分：ASR 给 WER，说话人验证给 SIM。
然后合成为一个 prompt-局部的**序数奖励**：

```
R_{g,i} = Ψ_g( −WER_{g,i} , SIM_{g,i} )

Ψ_g 的语义：先按内容正确性排序；只有在语言质量相当的候选之间，才用音色相似度打破平局
```

**为什么不用加权和 $R = -\alpha\cdot\text{WER} + \beta\cdot\text{SIM}$？** 论文给了两条理由：

| 理由 | 展开 |
|---|---|
| 语音指标的**尺度和可靠性会漂** | 随语言、转录长度、prompt 难度、参考条件而变。组内比较（同一个 prompt 下的候选互比）能消掉这些异质性 |
| 序数组合**不需要标定** | 加权和要求你把 WER 和 SIM 这两个量纲完全不同的异质奖励模型做数值标定，选 $\alpha,\beta$；字典序绕开了整个问题 |

而且更新**只在能提供有意义相对偏好信号的组上做**（组内全平手就跳过，因为
$\sigma_g\to 0$ 时优势没有信息量，只会放大噪声）。

### 论文自己承认的局限

> "The reward is observed only after the generated token sequence has been decoded
> into a waveform. Consequently, the shared trajectory advantage provides **coarse
> rather than token-specific credit assignment**."

奖励只有在解码成波形后才能观测，所以整条轨迹共享一个优势，
**信用分配是粗粒度的**——模型知道"这次说得好/不好"，但不知道是哪几个 token 的功劳。
论文明说这是拿细粒度信用分配换"与黑箱语音指标 + 原生掩码解码稳定集成"。

## 三、情感与非语言发声（NVV）：不加控制头

**NVV** = non-verbal vocalization，非语言发声，指笑声、叹息、喘息、咳嗽、清嗓、
咂舌、吸气这类不构成词汇但携带大量交流信息的声音。

设计上最值得注意的一点：**这些控制不走额外模块，直接当文本提示喂进去**。

```
输入文本： [happy] 这个消息太好了 [laughs] 我简直不敢相信
           └─句级─┘                └─行内─┘
           情感标签                 NVV 事件标签

           ↓ 走的是文本侧的条件通路，与普通文本同一条路径

  · 不需要 style encoder
  · 不需要 control head
  · 这些特殊 token 不会被当作词汇内容念出来
  · 行内 NVV 标签指定的是【文本相对位置】，不是精确的声学时间戳
  · 说话人身份仍由声学提示 P 单独指定（与情感解耦）
```

对比之下，同类系统通常要加一个风格编码器或专门的控制头。
把控制信号放进文本通路的好处是：它天然继承了 LLM 对上下文的理解能力，
`[laughs]` 放在哪个词后面，模型能从语义上理解那个位置的语气。

### 数据是怎么标的

值得记一笔的是标注流程，因为它是"用大模型给大模型造数据"的一个具体样本：

```
音频 + 转录
    ↓
Gemini 3.1 Pro Preview + 其他大型音频语言模型  ← 多模型【交叉核对】
    ↓  提出句级情感标签 + 行内 NVV 事件
分歧 / 低置信 / 事件边界复杂的样本
    ↓
人工复核  ← 同时用人工抽检来【校准和审计】整个流程
    ↓
按音频质量、转录质量、标签可靠性、去重过滤
```

标签体系是**收敛**的：同义或相近的来源标签映射到规范类别，
歧义、标注不一致、样本过少的类别直接剔除。保留标准是四条：
可感知区分、样本充足、可一致标注、对合成控制有用。

## 四、训练全流程（论文 Table 4）

| 阶段 | 数据 | 训练量 | 目的 |
|---|---|---|---|
| **基础预训练** | 完整多语言混合 | ~100 万小时；~1.1 加权 epoch；**~1000 亿打包 token** | 从 Qwen3-0.6B 学会多语言语音生成 |
| **高质量退火** | 精选高质量语音 | ~10 万小时池，约 1 epoch | 提升保真度、鲁棒性、自然韵律 |
| **表达性继续预训练** | 情感 + NVV 标注语音，混入中性语音 | 紧凑的精标注池 | 加入独立与联合的表达控制 |
| **块适配** | 多语言混合 | 约 **2 万** 优化步 | 学会块因果流式与终止判断 |
| **RL 后训练** | — | — | 优化 WER / SIM 这类句级属性 |

学习率细节（对复现有用）：基础预训练用 cosine schedule，峰值
$2.1\times 10^{-4}$，退到峰值的 $0.1\times$。

**高质量退火阶段有个容易忽略的做法**：切换数据集时**不重启学习率**，
而是沿用既有 schedule 当前的值，"ensuring a smooth transition when switching datasets"。
论文报告这个阶段在同样推理设置下持续改善 CV3-Eval 的四语言平均 WER。

> 这条对本仓库有直接参考价值：换数据源时重启 LR 会给模型一次不必要的冲击，
> 而"沿用 schedule 当前点"是更保守、也更容易归因的做法
> （改动只有一处：数据分布）。

**块适配阶段**保留 tokenizer、声学 embedding 空间、Transformer 权重、预测头，
只做两件事：全局双向掩码换成两流块因果掩码；序列级噪声换成**每块独立采样**的噪声水平。
另外训练和推理用同一套条件/无条件块几何，且"终止目标在语音正好结束于块边界时也存在"
（避免模型学到"块满了就一定还有下文"的错误相关）。
