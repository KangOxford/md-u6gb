# 05 · 对本仓库生成模型工作的可迁移点

本仓库的相关工作：LOB message 的 token 级自回归生成（S5 / Mamba3 / hybrid）、
LOB 上的扩散（noise-covariance diffusion）、GRPO 后训练、以及 tokenizer 设计
（24-token base-100 编码、无损 BPE 词表）。

下面五条按"可迁移性"排序，第 1 条最直接可做，第 5 条是方法论层面的提醒。

---

## 1. 「输出被输入约束吗」是一个可以拿来自查的判据

Luna-TTS 整篇的支点是这一句：

> TTS 的输出被输入文本高度约束，这**压塌了语义分支因子**，
> 而正是分支因子让自由文本的并行解码变得困难。

这句话的逆否命题才是有用的形式：

```
如果    输出的"说什么"被条件基本定死，只剩"怎么说"是自由的
并且    输出结构在某个轴上没有天然全序
那么    从左到右生成是【你自己加的】约束，不是任务固有的
```

**拿 LOB 生成来套一遍：**

| LOB message 的成分 | 被约束吗 | 有天然顺序吗 |
|---|---|---|
| 事件时间戳 | 强约束（单调递增，且受市场活跃度分布约束） | ✅ 时间轴天然有序 |
| 事件类型（新单/撤单/成交） | 弱约束（这是模型要预测的核心随机性） | — |
| 价格 | **强约束**：必须落在 tick 网格上，且强烈受当前 best bid/ask 约束 | ❌ 一条消息的各字段之间无天然先后 |
| 数量 | 中等约束（受挂单量分布约束） | ❌ 同上 |
| 方向 | 弱约束 | ❌ 同上 |

**结论：LOB 的时间轴天然有序（该保持 AR），但一条消息内部的 24 个 token
在字段之间没有天然全序**——它们现在的顺序是编码方案定的，不是数据定的。
这与 RVQ 的深度轴处境完全同构。

**可做的最小实验**：保持时间轴 AR 不变，把**帧内（单条 message 内）的 token
改成并行预测**——正是 Luna-TTS 的 "$Q$ 个并行头 + 帧 embedding 求和" 做法。

```
现在:  msg_t 的 24 个 token  ──► 24 个串行 AR 步
提议:  msg_t 的 24 个 token  ──► 1 个序列位置（各字段 embedding 求和）
                              ──► 24 个并行分类头

序列长度 ÷24，串行步数 ÷24
```

论文对这个做法的表述是 "keeps the Transformer sequence length at $T$ rather than $TQ$"。
对本仓库意味着**上下文长度按字段数倍数放大**——2k 上下文能装的消息数直接乘以 24。
这对 `project_hybrid_ctx2k_verdict` 那条线（长上下文优势随距离单调放大）是个
免费的杠杆。

> ⚠️ 需要先验证的前提：字段之间的**条件独立性假设**在 LOB 上成不成立。
> 求和 embedding + 并行头，隐含"给定帧的 hidden state，各字段条件独立"。
> RVQ 靠多步迭代精炼来补这个假设的不足（第 2 步能看到第 1 步提交的结果）。
> LOB 上价格与数量高度相关，可能同样需要迭代精炼，而不是一次并行到底。

## 2. Block Diffusion 是"AR 程度"的连续旋钮

论文最干净的一个贡献是把 AR 与全并行放在**同一条轴**上：

```
块大小 B = 1         ────────────────────────►      B = T（全长）
  纯 AR                                            全并行掩码扩散
  串行 NFE = O(T)                                  串行 NFE = S（常数）
  可流式、可 KV cache                               不可流式
  误差前缀无界传播                                   全局可精炼
                    ↑
              B = 32 帧（1.28 s）
              Luna-TTS Realtime 选的工作点
```

这和本仓库 hybrid（Mamba3 + attention）的设计是**同一类问题的两个实例**：
"用哪种机制处理哪段距离"。区别在于——

| | hybrid Mamba3 | Block Diffusion |
|---|---|---|
| 旋钮是什么 | 层的配比 / 哪几层放 attention | 块大小 $B$ |
| 旋钮在哪里生效 | 架构（训练时定死） | **架构 + 推理**（训练时定块因果，推理时块大小固定） |
| 代价结构 | 长程能力 vs 计算 | 延迟粒度 vs 可修正性 |

**值得借鉴的是论文暴露这个旋钮的方式**：它训练了**两个共享一切的变体**
（同 tokenizer、同数据、同骨干、同 lineage），只差生成范式，
于是它们构成"AR–扩散插值的一个受控实现"。论文原话：

> "Choosing between them is a **deployment decision, not a system migration**."

这是很高的实验卫生标准。对照本仓库的做法：`project_hybrid_pmatch_arm`
（缩窄 hybrid 的 attn FFN 而非加宽 baseline 来配平参数量）就是同一个原则——
**让两条臂只差你想研究的那一件事**。

论文自己在 Limitations 里承认 1.28 s 的块大小是**写死的、不随内容自适应**，
并把"动态块大小"列进 Future Work。这条对本仓库同样成立：
LOB 的事件密度波动极大（开盘 vs 午盘），固定块大小几乎肯定不是最优。

## 3. 多码本的层次解耦：CB1 放语义，CB2–CB8 放细节

Luna-Codec 的做法是给第一层码本加一个 **WavLM 语义蒸馏 loss**，
强行让深度轴按"语言信息 → 声学信息"排序，理由是：

> 纯声学 RVQ 会把精细频谱细节**前置**到早期码本，让 token 序列
> "unnecessarily hard to predict from text"（**不必要地**难以从文本预测）。

**对本仓库 LOB tokenizer 的映射：**

| Luna-Codec | LOB 类比 |
|---|---|
| CB1 = 语言/字音骨架（被蒸馏锚定） | 事件类型 + 方向（决定"发生了什么"的骨架） |
| CB2–CB8 = 音色、韵律、环境、情绪 | 价格偏移、数量、时间间隔的细节 |
| 蒸馏源 = 预训练 WavLM 表征 | 类比物 = ？ |

**这个类比的断点在最后一行**：LOB 上没有现成的"WavLM"可蒸馏。
但锚定不一定要靠外部模型，也可以靠**辅助预测任务**——
比如要求第一层 token 足以预测"下一秒的 mid-price 方向"或"该事件是否成交"，
把第一层逼成一个语义骨架层。

**更直接可用的是那个诊断信号本身**：

> 如果你的 tokenizer 的第一层 token **从条件难以预测**，
> 那么难度可能是 tokenizer 训练方式造出来的，不是任务固有的。

这可以做成一个廉价的检查：拿现有的 LOB 编码，逐字段测"给定历史，
该字段的条件熵是多少"。如果某个本该是骨架的字段（事件类型）条件熵异常高，
而某个本该是细节的字段反而低，说明编码的信息分层是反的。
成本是一次前向遍历，不用训练。

> 相关记忆：`feedback_positional_encoding_breaks_ordinal_metric`（位置制编码毁掉序数度量）
> 和 `feedback_absorbing_state_from_isolated_token`（孤立 token 造成吸收态）——
> 都是"编码方案本身制造了学习困难"这一族。Luna-Codec 是这一族问题的
> **正面解法样本**：不要改模型，改编码的信息分层。

## 4. GRPO 在非 AR 模型上：轨迹感知 ratio 是现成配方

本仓库跑过 GRPO（G=512 / G=1024，见 `feedback_grpo_must_have_resume`）。
如果将来要把 RL 后训练用到扩散式或并行式的 LOB 生成上，
论文 §4 给的是一份**可以直接抄的配方**。三个要点：

**(a) 不要试图算最终序列的似然，在实际走过的轨迹上算。**

```
记录:  τ = { (s_k, M_k, a_k) }_{k=0}^{S-1}     每步：状态、解掩位置集、采样值
ratio: r_{g,i,j} = exp( log π_θ(a_j|z_j) − log π_old(a_j|z_j) )
       ↑ 逐【已提交的 token 决策】算，不是逐序列
```

**(b) ⚠️ 最容易踩的坑：rollout 与 replay 必须在同一个「有效策略族」下算概率。**

论文的措辞值得原样记住：

> "ratios computed from the **untransformed** model distribution need not correspond
> to the distribution that generated the speech tokens."

也就是说，$\pi_\theta$ 必须定义为**施加了解码器全部变换之后**的分布：
合法性约束、top-$k$ 截断、温度、**以及 CFG**。

这条对本仓库直接适用，而且是那种**不会报错、只会给出错误结论**的缺陷：
如果采样时用了 top-k / 温度 / 任何 guidance，而记账时用原始 logits 算 log-prob，
ratio 从定义上就不是重要性比，PPO 裁剪也就失去意义。训练照跑、loss 照降、
wandb 照记——和 `feedback_derive_k_from_effective_batch`（梯度累积 K 被悄悄改掉）
是完全同一族的问题：**配置没到达它该到达的地方，而系统不会告诉你**。

**(c) 奖励用字典序，不用加权和。**

```
R = Ψ( −WER, SIM )      先按内容正确性排，平手时才用音色相似度打破平局
```

两条理由都能平移到 LOB：

| 论文的理由 | LOB 上的对应 |
|---|---|
| 语音指标的尺度随语言/长度/难度漂移 | LOB 指标的尺度随 ticker / 波动率 regime / 时段漂移 —— 完全一样 |
| 加权和要求标定异质奖励模型 | LOB-Bench 的多个维度（分布距离、order flow、价格影响）量纲完全不同，选权重就是在偷偷定义"什么叫好" |

而且**组内比较**（同一个 prompt 下的候选互比）天然消掉了跨条件的异质性——
这和记忆里 `feedback_day_block_bootstrap_flips_single_day`（日块 bootstrap）
的思路一致：**在正确的分组内比较，而不是把所有样本拉平**。

**(d) 论文自己承认的局限也要抄下来**：奖励只有解码成波形后才能观测，
所以整条轨迹共享一个优势，**信用分配是粗粒度的**。
如果 LOB 的奖励也只能在整条序列生成完后算（比如 LOB-Bench 分数），
就会有同样的问题，别指望它能定位到"是哪几个 token 错了"。

## 5. 方法论：这篇稿子本身是一个反面样本

`04` 里查出的两处拼接，都不是罕见错误，而是本仓库自己反复吃过的亏的**公开版本**：

| 稿子的做法 | 本仓库的对应教训 |
|---|---|
| 把 Luna-TTS 的质量 + Realtime 的延迟合成"六项第一" | `feedback_artifact_name_carries_checkpoint_identity` —— **产物名必须带 checkpoint 身份**。两个 checkpoint 的最好数字合成一句战报，读者无法反推 |
| 把 ⋄（引用他人报告）和 †（同协议复现）混在一张表里，还把论文的 caveat 删掉 | `feedback_two_premises_before_comparing` —— **比较前的两个前提**。表格的形状会暗示一种它并不具备的可比性 |
| 用 Elo（盲测投票）去印证 CER（客观错误率） | `feedback_new_axis_is_not_useful_axis` / `feedback_ratio_and_level_can_diverge` —— 两个不可换算的量被当成互相支持的证据 |
| "第三名"被写成"碾压"（论文原话：不显著） | `feedback_separate_eval_noise_from_seed_noise` —— **差异必须先过噪声门**。bootstrap 区间重叠就是"没测出差别"，不是"赢了一点点" |
| 只报四语言里赢的两种，不报输的两种和平均 | `feedback_slope_hides_the_level` / `feedback_level_and_slope_are_two_claims` —— 挑对自己有利的切面报告 |

**值得单独记一笔的是论文的正面示范**：它把 ⋄/† 标出来了、把 bootstrap 区间给出来了、
把"不显著"明写了、把 Limitations 写了（韩语最弱、只 4 语言、duration predictor 是外挂、
块大小写死）。这是一份技术报告该有的样子，而它做到了。

**所以这份材料的真正用法**，不是"看看别人怎么吹"，而是：
一份写得诚实的技术报告 + 一份基于它的宣传稿，摆在一起，
就是"信息在传播链上如何失真"的一个完整标本。

## 附：如果要做一个最小验证实验

按投入从小到大排：

| # | 实验 | 成本 | 能回答什么 |
|---:|---|---|---|
| 1 | 逐字段测 LOB 编码的条件熵，看信息分层是否与设计意图一致 | 一次前向遍历，无需训练 | 第 3 条的诊断信号是否在 LOB 上亮起 |
| 2 | 帧内并行头改造：24 token → 1 序列位置 + 24 个头，小模型跑通 | 一次小规模训练 | 序列长度 ÷24 后，等效上下文变长的收益是否真实；字段条件独立假设的代价多大 |
| 3 | 在 2 的基础上加 2–4 步迭代精炼（置信度解掩） | 增量训练 | 迭代精炼能否补回条件独立假设的损失 |
| 4 | 块因果版本：块间 AR、块内并行，块大小扫 1/4/16 条消息 | 一组对照臂 | Block Diffusion 那个旋钮在 LOB 上的最优点在哪 |

第 1 项现在就能做，而且**在登录节点上就够跑**（纯 CPU、单次、顺序读，
符合 CLAUDE.md 的小型 CPU 实验豁免条件）。
