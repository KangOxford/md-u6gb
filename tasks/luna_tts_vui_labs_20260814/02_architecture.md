# 02 · 架构：为什么要把 TTS 从自回归改成扩散

内容全部来自论文 arXiv:2608.11593 §1–§2，公众号的技术段落是它的转述。

---

## 0. 先把名词钉住

| 术语 | 中文/展开 | 一句话解释 |
|---|---|---|
| **AR** | autoregressive，自回归 | 从左到右一个 token 一个 token 生成，每步都以已生成的前缀为条件 |
| **NAR** | non-autoregressive | 不按固定顺序，一次并行产出多个位置 |
| **RVQ** | Residual Vector Quantization，残差向量量化 | 把一帧音频用**一叠**码本条目表示：第 1 层给个粗略近似，第 2 层编码"第 1 层的残差"，逐层细化。所以一段音频不是一维序列，是 `帧数 × 码本层数` 的**二维网格** |
| **codec / tokenizer** | 神经音频编解码器 | 把波形压成离散 token，再解回波形。TTS 语言模型生成的就是这些 token |
| **masked diffusion** | 掩码扩散 | 一种离散扩散：加噪 = 把 token 换成特殊的 `[MASK]`；去噪 = 预测被遮住的位置。与图像的高斯扩散不同，它在**离散**空间上做 |
| **absorbing state** | 吸收态 | `[MASK]` 是吸收态：一旦一个位置变成 MASK，前向过程就不再改它。这让前向过程有闭式解，训练目标退化成"加权的填空交叉熵" |
| **exposure bias** | 暴露偏差 | 训练时喂真实前缀，推理时喂自己生成的前缀。一旦采错，错误进入前缀且**永久冻结**，后面全部基于错误继续 |
| **CFG** | Classifier-Free Guidance | 同时算"给文本条件"和"不给文本条件"两路输出，把两者的差放大，用来加强对文本的遵循度。代价是每步要算两次前向 |
| **dLLM** | diffusion language model | 用掩码扩散做的语言模型（LLaDA、Dream 等），相对 AR LLM 的新范式 |
| **block diffusion** | 块扩散 | 块之间自回归、块内部并行去噪。是 AR 与全并行之间的连续插值，块大小 = 1 时退化为 AR，块 = 全长时退化为全并行 |
| **NFE** | number of function evaluations | 串行前向次数，衡量"必须一步接一步做多少次"，决定延迟下界 |

## 1. 问题：AR 在 TTS 上有三重结构性代价

主流 TTS（Seed-TTS、CosyVoice、MiniMax-Speech、Qwen3-TTS、GLM-TTS……）
共享同一个计算内核：**一个从左到右吐 speech token 的 AR 语言模型**。
论文列出它的三个代价：

```
代价 1 · 解码是串行的
   延迟和算力随生成步数线性增长，而步数 = 音频时长 × token 率
   RVQ 让问题更糟：每帧有 Q 层码本，AR 必须在"深度轴"上也强加一个顺序
   ——而深度轴根本没有天然的先后

代价 2 · 暴露偏差 + 误差累积
   采样错一次 → 冻进前缀 → 一路传下去
   表现为跳字、重复、吞音（业界为压制它专门设训练阶段）

代价 3 · 生成顺序写死，无法双向精炼
   AR 不能回头根据后文修改前面的帧
   speech editing（改一句话中间的某段）需要额外机制，不是原生能力
```

业界对代价 1 的回应，是一整套**打补丁的生态**，论文点名了三类：

| 补丁 | 做法 | 谁在用 |
|---|---|---|
| delay / interleave pattern | 让不同码本流错开若干帧，制造一个人为的可 AR 化顺序 | MusicGen 系、MOSS-TTS |
| 时间–深度分层 AR | 大模型管时间轴，配一个轻量的帧内解码器管深度轴 | Moshi、MOSS-TTS、Fish Audio S2 |
| 多码本预测头（MTP） | 从共享的时间状态一次预测多个残差码本 | Qwen3-TTS |

论文的判断很直接：**这三个都是在同一个约束上做越来越精巧的补丁。**

## 2. 关键洞察：TTS 的输出被输入高度约束

这是整篇论文的支点，也是最值得记住的一句：

> "the output is strongly grounded in the input text, which **collapses the semantic
> branching factor** that makes parallel decoding difficult for free-form text generation;
> and the RVQ token grid is precisely the kind of **order-free, locally correlated
> structure** that any-order masked prediction handles natively and AR decoding does not."

拆成两半：

**(a) 语义分支因子被压塌了。** 自由文本生成里，"今天天气"后面可以接无数种延续，
并行解码难在各个位置的选择互相依赖、组合爆炸。TTS 不是：给定输入文本"今天天气真好"，
输出音频**说什么内容已经定死了**，模型只需要决定怎么说（音色、韵律、情绪）。
分支因子塌缩，并行解码的主要障碍就消失了。

**(b) RVQ 网格本来就没有全序。** 时间轴有先后，但**深度轴（码本层）没有**。
第 3 层码本和第 5 层码本谁先谁后，是架构强加的，不是数据固有的。
掩码扩散对所有网格位置**对称**建模，跨码本依赖靠迭代精炼解决，
而不是靠架构里写死一个顺序。

> **这个判据可以拿来自查其他任务**：如果你的输出被输入强约束、且输出结构没有天然全序，
> 那么"从左到右生成"很可能是你自己加的、不必要的约束。见 `05_takeaways.md`。

## 3. 三步走：从文本 LLM 到语音扩散模型

论文没有从头训练，而是**逐级改注意力掩码 + 继续训练**：

```
   Qwen3-0.6B                 Luna-TTS                    Luna-TTS Realtime
   ┌──────────┐               ┌──────────┐                ┌──────────┐
   │  causal  │  直接转换      │bidirect- │  块因果适配     │  block-  │
   │   AR     │ ───────────►  │  ional   │ ────────────►  │  causal  │
   │  文本    │  100 万小时    │ 全并行   │  ~2 万步       │  流式    │
   └──────────┘  继续预训练    └──────────┘                └──────────┘
   文本能力         ▲              ▲                            ▲
   （G2P规则、    保留          保留 tokenizer /             保留全部
    命名实体、                   embedding / 骨干 /            权重与
    日韩书写系统）               预测头                        预测头
```

**为什么要从文本 LLM 起步。** 论文给了两条理由：
(i) 文本能力（字形到音素的规律、命名实体、语码混合、日语汉字假名混写、韩语谚文）
从"语音-文本配对数据"里学代价极高；
(ii) 已有工作表明 AR 初始化的扩散模型**收敛显著快于**从头训练。

每一步只改注意力掩码 + 换训练目标，其余全部继承。论文强调这个配方
"applies to any existing codec language model"（对任何现有 codec 语言模型都适用）。

## 4. 训练目标：吸收态掩码扩散

设目标 token 网格 $\bm{X}_0 \in \mathcal{V}^{T\times Q}$（$T$ 帧 × $Q$ 码本），
条件 $\bm{c}=(\bm{y}, \bm{P})$ = 文本 + 可选的声学提示（参考音色）。

**前向（加噪）**：给定噪声水平 $t\in(0,1]$，每个位置**独立**地以概率 $t$ 被换成 `[MASK]`：

```
q_t(X_t | X_0) = ∏_{i=1}^{T} ∏_{q=1}^{Q} [ t·δ_M(X_t^{i,q}) + (1-t)·δ_{X_0^{i,q}}(X_t^{i,q}) ]
```

条件 token 永不被 mask。

**反向（训练目标）**：并行恢复所有被遮位置，得到加权去噪交叉熵（它是负对数似然的上界）：

```
L_MD(θ) = - E_{t~U(0,1]} E_{X_t~q_t} [ (1/t) · Σ_{(i,q): X_t^{i,q}=M} log p_θ(X_0^{i,q} | X_t, c) ]
```

`1/t` 这个权重是重要性加权：噪声水平低（遮得少）时每个被遮位置更"信息量大"，
权重就更高。

**帧级多码本处理**（这是个实现上的关键选择）：

```
输入侧：一帧的 Q=8 个码本 embedding 从 8 张表里查出来，然后【相加】成一个帧向量
        → Transformer 的序列长度是 T，不是 T×Q      ← 省 8 倍序列长度
        → LM 侧的速率保持在 25 Hz

输出侧：每帧的 hidden state 喂给【Q 个并行分类头】，一头一个码本
        → 一次前向同时预测该帧全部 8 层
```

部分遮蔽也支持：某一帧可以只遮深度轴上的一部分，被遮的码本用一个
**可学习的 per-codebook mask embedding** 参与求和。

文本 embedding、位置编码、文本头**原封不动**继承自 Qwen3-0.6B；
音频 embedding 表和 8 个音频头是新加的参数。

## 5. Luna-TTS：全并行，$S=32$ 步

```
起点：整张 T×Q 网格全是 [MASK]
      ↓  第 1 步：模型并行预测所有位置 → 按置信度提交一小部分 → 其余重新 mask
      ↓  第 2 步：同上（已提交的位置作为上下文）
      ⋮   （cosine 调度决定每步提交多少）
      ↓  第 32 步：全部提交
结果：完整音频
```

**置信度解掩（confidence-based unmasking）**，沿用 MaskGIT 家族的做法：
每步模型预测全部被遮位置，按 cosine 调度选出一定比例**提交**，
选取依据是预测置信度加退火的 Gumbel 噪声，其余重新遮住进下一轮。

因为训练用的是**无限制随机遮蔽**（时间轴和深度轴都不加结构约束），
解码器可以**按置信度想先定哪里就先定哪里**，跨时间、跨码本深度都行，
而不是被架构固定顺序。

三个由此白拿的能力：

| 能力 | 为什么是免费的 |
|---|---|
| **零样本音色克隆** | 输入序列是 `[文本; 干净的提示网格 P; 部分遮蔽的目标网格 X_t]`。提示只是同一张网格里**没被遮的一块**，所以克隆不是特殊机制，就是模型原生的 infilling |
| **语音编辑** | 把已有音频的任意一段遮掉，按原文或改过的文本去噪，重新生成那一段并与前后文保持连贯。AR 模型做不到这点，除非加专门机制 |
| **语速控制** | 帧数 $T$ 是外部给的，用户可以直接改或缩放它 |

**代价：必须先知道帧数 $T$。** 全并行要先把画布铺好。规则式估长（字数 × 语速）
在四种语言上很脆（中文字符≈音节、日语汉字+假名混写、韩语谚文、英文拉丁字母，
文本长度到时长的映射差别很大）。所以他们**另外训了一个 duration predictor**：
一个独立的 Qwen3-0.6B，改成全双向注意力，读完整句子后**并行预测每个文本 token 的时长分布**，
监督来自强制对齐，推理时取期望再求和得到 $T$。

> 这是个"为了一个能力付出一个额外模型"的典型折衷。论文在 Limitations 里
> 把"duration predictor 是外挂的"列为待改进项，Future Work 提到要把它整合进骨干。

**另一个代价：不能流式。** 见 `04_numbers_and_claims.md` 第一节的图示。

## 6. Luna-TTS Realtime：只在块边界上引入因果性

把时间轴切成 $N=\lceil T/B \rceil$ 块（$B=32$ 帧 $=1.28$ 秒）：

```
p_θ(X | c) = ∏_{b=1}^{N} p_θ( X^(b) | X^(<b), c )
             └──────┬──────┘
              块之间是自回归的（有序）
              块内部的帧和码本【没有顺序】——整块作为一个联合声学结构一起精炼
```

```
     ┌─ 块 1 ─┐  ┌─ 块 2 ─┐  ┌─ 块 3 ─┐
     │ 8 步并 │  │ 8 步并 │  │ 8 步并 │      每块内：32 帧 × 8 码本 = 256 个位置
     │ 行去噪 │  │ 行去噪 │  │ 行去噪 │      一次并行去噪，8~16 步出结果
     └───┬────┘  └───┬────┘  └───┬────┘
         │ commit    │ commit    │ commit
         ▼           ▼           ▼
      ♪ 播放      ♪ 播放      ♪ 播放          块一提交就送 codec 解码播放
         └──── KV cache 累积（块因果 → 可缓存）────►
```

关键点：

- **块因果是训练出来的，不是推理时改掩码改出来的。** 论文特意声明
  "Block causality is therefore part of the learned generation behavior, rather than
  an inference-time masking modification alone"。训练时就按流式执行时能拿到的信息
  去预测被破坏的当前块，并且**每块独立采样噪声水平**。
- **提交即不可变。** 已完成的块是 immutable context，只有当前块可改。
  好处是 KV cache 能用、音频能边算边送；代价是早期错误无法回头修
  （这直接解释了 hard 子集上的性能崩塌，见 04）。
- **结束靠学出来的 EOS**，不是 duration predictor。外加一个最大长度作为服务兜底。

## 7. 三种范式的对照（论文 Table 1）

| | AR codec LM | Luna-TTS | Luna-TTS Realtime |
|---|---|---|---|
| 生成顺序 | 固定，左到右 | 任意顺序，全局 | 块内任意，块间左到右 |
| **串行 NFE** | $\mathcal{O}(T)$–$\mathcal{O}(TQ)$ | $S$（**常数**） | $S_b\lceil T/B\rceil$ |
| KV cache | ✓ | — | ✓ |
| 流式 | ✓ | — | ✓（1.28 s 块） |
| 长度处理 | stop token | duration predictor | stop token |
| 帧内码本 | delay / 深度AR / MTP | 原生并行 | 原生并行 |
| infilling & 编辑 | 需专门机制 | **原生** | 前缀受限 |
| 误差传播 | 前缀无界 | 迭代精炼可修 | 块内可修，**提交后不可逆** |
| 适合负载 | — | 离线 / 批量 | 流式 / 交互 |

论文对这张表的定性："**We regard neither variant as dominant**"（两个变体都不占优），
它们是同一个模型族的两个工作点，因为生产负载本来就分裂成
"吞吐受限的离线合成"和"延迟受限的交互合成"两类。

**串行 NFE 那一行是整个工作的收益所在**：AR 是 $\mathcal{O}(T)$ 起步
（用了 delay pattern 之类还会更差），Luna-TTS 是**与音频长度无关的常数 32**。
这就是 RTF 能做到 0.0211 的原因，不是靠工程优化堆出来的，是复杂度阶数变了。

## 8. 工程侧

- **服务栈**：vLLM-Omni。CFG 的两路（有条件 / 无条件）可以串行跑在 1 张卡上，
  也可以拆到 2 张卡并行。论文声明并行实现"preserves identical acoustic tokens and
  waveform bytes"（产出逐字节相同），所以这是纯粹的延迟优化。
  实测把完整响应延迟砍掉 46.1%（16 步）/ 44.5%（8 步）。
- **文本正则化前端**：数字、特殊符号等易读错的文本走专门的预处理模块。
- **Luna-Codec 是因果的**，解码器逐帧同步重建波形，所以块一提交就能出声，
  不用等整段。
