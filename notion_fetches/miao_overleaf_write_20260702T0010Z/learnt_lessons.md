# Learnt Lessons

- Do not assume a new Overleaf link is the same as the old paper clone; verify `git remote -v`.
- Overleaf Git can hang without returning a clear authentication error in this environment, so use bounded `timeout` probes and do not leave sessions running.
- When Overleaf access is blocked, the safe deliverable is a Notion-backed writing plan and audit, not a claim that the paper was written into `.tex`.
- The current CHARLS paper should start Overleaf drafting from the empirical section because that is where the evidence is already validated.
- For this paper, the Notion-first draft should be Chinese prose, not only LaTeX, because the user's immediate writing target is the paper text and Notion is the reachable collaboration surface.
- Policy interpretation should not stop at "raise pensions"; the stronger writing move is to connect pension stability to psychological welfare, living-alone vulnerability, and coordination with community services and long-term care insurance.
- For the 3.8 policy section, avoid a policy inventory. The user prefers three high-signal points tied directly to the empirical results over six-point institutional coverage.
- When expanding the CHARLS draft into a full paper, create a child page rather than overwriting the already verified empirical-section page; keep the parent page as the audit trail with the struck-through prompt and child-page link.
- In full-paper drafting, do not invent missing table metadata such as sample size or descriptive means; write the narrative around validated coefficients and mark final table metadata as a later fill-in.
